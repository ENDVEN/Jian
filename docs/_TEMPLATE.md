# <文档标题>

> 一句话说清"这份文档解决什么问题"。

## 头部契约（必须，前 8 行）

| 字段 | 取值 | 作用 |
|---|---|---|
| `status` | `active`（在办）· `done`（已完成）· `reference`（长期参考）· `history`（历史） | **agent 只读 active**，别读 done/history |
| `topic` | 一句话主题 | 检索用 |
| `read_when` | 什么任务该读我 | 决定"要不要继续读" |
| `skip_if` | 什么情况下别读我 | 减少无效读取 |
| `verified` | 最后核对日期 | 防止读到过期数字 |

## 正文结构（推荐）

1. **结论先行**：3~5 行内说清"是什么 / 现在什么状态 / 要不要做"；
2. **实测基线**：带数字与日期（不写"很快/很多"这种词）；
3. **口径与决定**：写"为什么这么定"，别只写"这么做"；
4. **步骤清单**：每步带验收方式与估时；
5. **风险与不做**：明确"哪些我们不做"，防止后人反复提；
6. **待确认**：需要用户拍板的点，编号列出。

## 硬规矩

- **例外**：根目录 `README.md` 是**产品页**（给访客看），**不加 front-matter** —— GitHub 会把
  YAML 头渲染成一条横线加一段文字，很难看；它的"状态"由 `docs/STATUS.md` 承担。

- 版本号**不写**（唯一真源 = `version.json`）；断言数**不写**（→ `docs/STATUS.md`）；文件行数**不写**（→ `CODEMAP`）。
- 已完成 ⇒ 移到 `docs/plans/done/`，并在 `docs/plans/README.md` 里留一行。
- 任何"当前状态"类句子必须带日期。
