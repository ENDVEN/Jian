### 11.5 最容易踩的坑（血泪，别重犯，**持续累积** — 不写条数上限，写了必然滞后）
1. **净额 = `net_profit − commission`**。任何"结果类"指标（胜率/盈亏比/极值/净值曲线）
   漏掉手续费就是造假。已知 `yearly_review.py` 就踩了这个坑（§9-F）。
2. **`trade_time` 永远是纯日期 00:00:00**，绝不自动填时分；真实时刻放 `*_fill_time`。
   没有开仓时间就显示 `—`，**绝不猜**。
3. **任何"看起来能填其实源里没有"的值，一律 `—`/降级**，不要 0、不要 00:00、不要编。
4. **DB 一律 `INSERT OR IGNORE`**，`internal_id` = MD5 确定性哈希（FIFO 切片会追加 `#i` 盐）。
   改哈希规则 = 让老库防重失效，**千万别动**。
5. **FIFO 必须全局排序后只跑一次**（按 日期→时刻→序号），这是"分批导入 ≡ 一次性导入"的地基。
6. **耗时 I/O 一律 QThread**：导入解析、拉个股行情、拉指数、回测计算、版本检测，共 5 处。
7. **别给复合控件写半截 QSS**（§10-9）：`QSpinBox/QDoubleSpinBox/QComboBox/QDateEdit`
   只写本体不写子控件 ⇒ 箭头图标漂移 + 点击热区错位。要美化就写全，并收敛到
   `custom_widgets.py`。
8. **行情同步两大铁则**（§9-M，改 `sync_service.py` 前必读）：
   ① "已最新"判据必须是**末日==今天**（`fresh_within_days=0`）——放宽=增量永远滞后一天拿不到当日 bar；
   ② **空增量 = 已最新不是失败**——增量模式只请求一次、空返回即 `skipped`，不重试不熔断。
   数据起点保持 2010（个股全历史），评估窗才是 2016，两者别混。
9. **别让两套机制同时 toggle 同一个选择状态**（§9-N1）：Qt 原生 indicator 点击会**自动切换**，
   若你再监听 `cellClicked` 手动切换一次 = 双重触发 = 等于没点。要么只用原生、要么（推荐）
   完全自绘（☐/☑ 字符 + 整格点击唯一入口），且关掉行选择以免出现难看的选中高亮。
10. **别照着 docstring 改常量**（§9-O3 血的教训）：`sync_service.refresh_one` 的 docstring
    一度把数据起点写成 2016 而实际常量是 2010（v5.13 已改正）。**改任何常量前先看代码本体，
    再从代码反向修文档**；反过来做就是"静默回归"。
11. **同类防护要做就做全套**：`market.py` 有"同步结果 vs 当前标的"的竞态守卫，
    `backtest.py` 同场景却漏了（§9-O5，v5.13 已补齐）。加防护时全局搜一遍同一场景还有几处。
12. **图表样式只改 `ui/widgets/chart_style.py`**（§9-O7）：此前 4 处重复、改一处漏三处。
    且行情页传的是 **PlotItem**（`GraphicsLayoutWidget.addPlot()` 的返回值）不是 PlotWidget ——
    给图表封装公共函数前先想清楚"调用方手里到底是哪种类型"。
13. **【v5.13 修订 · Qt 布局坑】顶部栏末尾的 `QLabel` 会"吞掉"主区高度**：
    页面顶部一条 `QHBoxLayout`（搜索栏/标题/工具按钮），下方是 `QSplitter` 主区，
    只要顶部栏的**末尾**多了一个 `QLabel`（vertical sizePolicy = Preferred，而按钮/复选框是 Fixed），
    Qt 会把整段富余垂直空间全部分给顶部栏，标题会被拉到几百像素高、主区被压成 sizeHint。
    触发条件是"QLabel 在末尾"，换位置/换按钮都不会。
    **根治**：主区 widget 永远显式 `layout.addWidget(main_widget, 1)` 给 stretch>0，
    富余空间才不受 Qt 启发式影响。`backtest.py` 本来就这么写所以没翻车，
    `market.py` 原本忘了写，被 v5.13 新增的同步状态 QLabel 一脚踢翻。

    三条纪律：

    ③ 任何"把警告升级成错误"的改动，**上线前必须拿存量样本跑一遍**（本次是 `实例函数.txt`）。
15. **【v6.7 · Qt 动态控件的两条硬纪律】**（真实 Bug，用户截图驱动，见 §9-R）
    - **删除子控件必须 `setParent(None)` 再 `deleteLater()`**：只写
      `layout.removeWidget(w) + w.deleteLater()` 的话，在事件循环真正删除前，
      `w` 仍作为**可见子控件**挂在父控件上（只是不再受布局管理）—— 表现为
      "界面上凭空多出一个一模一样的控件"（本次 = 对话框里两个"函数段 1"）。
      **自检**：`parent.findChildren(QWidget, FindDirectChildrenOnly)` 的个数
      必须等于"布局里管着的个数"。
    - **容器分到多余高度时，必须有可伸缩的子控件来承接**：若子控件都是固定高度，
      Qt 会把空档**塞进容器内部**（标签被顶到最上、输入框被推到几百像素之外）。
      修法二选一：① 让真正该变大的控件 `Expanding`（**优先**，多余空间变成可用面积）；
      ② 在末尾 `addStretch(1)`（保底，只把空档赶到尾部）。
      ⚠ 这类问题**在滚动容器里不会显形**（子控件拿到的是 sizeHint），
      同一个组件搬到普通对话框就会暴露 —— 所以**给容器换环境时要重新看版面**。
16. **【v6.8 立项 / v6.15 已根治 · pyqtgraph 坐标轴的三个默认行为，全都不是我们要的】**
   （§7-B4 已落地，见 §9-S / §9-v6.15）
   ① `AxisItem.setTicks([...])` 是**一次性静态数据**，**不会随缩放更新** —— 我们的 x 是

   y 轴"看起来坏了/固定了"，其实是没人告诉它"用户现在只看得到这一段"。
   ③ 刻度密度与数字精度**不会**随缩放级别自适应，得按轴的像素长度和可视跨度自己算。
   → **统一解法（已落地）= `ui/widgets/adaptive_axis.py`**：
   `attach_date_axis(pane, dates|texts, y_provider=…)` / `attach_all(host, dates, providers)`；
   **禁止再在业务页面里手写 `setTicks` 或 `setYRange`** —— 页面只需回答
   "该窗格在可视区间内的数值范围"（provider 契约）。
   现存 3 处静态 ticks 已全部收敛（行情主图 / 复盘 K线回放 / 复盘资金K线，v6.15）；
   回测页两处（K线 / 净值）也已改为调用公共纯函数；另有 2 处类别轴（策略对比 / 年度复盘）
   与 1 处对数参考轴属"合理静态"，**不改造**（§7-B4 边界）。
17. **【v6.9 · 复合控件样式的"半截"会让箭头彻底消失】**（真实 Bug，§9-T1）：给
    `QComboBox / QDateEdit / QDateTimeEdit` 写 QSS 时，**只给 `::drop-down` 而不给
    `::down-arrow`，Qt 切到样式化绘制路径后箭头根本不会绘制**（离屏实测：箭头区域
    零深色像素）。这比"图标样式漂移"更隐蔽 —— 界面上看不出报错，只是**下拉控件看起来
    不像能点**（复盘页时间选择器、手工录入弹窗长期如此）。
    → **纪律**：① 复合控件样式**只准**用 `custom_widgets.combo_qss()/date_edit_qss()`
    或 8 个具名常量；② 要手写就必须 `::drop-down` + `::down-arrow` **成对**，箭头可用
    **border 三角**画（无需图片资源）；③ 新增变体后跑 `py tests/smoke_chart.py`，
    里面已有"箭头可见"的**像素级断言 + 负向对照**。
    附带教训：**凡是"样式改完看起来没问题"的判断，都要用离屏 grab 量像素证实一次** ——
    "肉眼没看出来"与"真的没坏"是两回事。
18. **【v6.10 · pandas Series 不能做布尔判断】**（真实踩到，P6 接线首日就炸）：
    写 `dates or []`、`points or []`、`x if x else y` 这类"空值兜底"时，只要 `x` 可能是
    **pandas Series**，就会抛
    `ValueError: The truth value of a Series is ambiguous`。
    本项目里 **UI 会把 `df['date']` 直接传进公共组件**（行情页 → 标注层 → `DateAxis`），
    所以公共件里**一律用 `x if x is not None else []`**，禁用 `or []`。
    同类高危写法：`if series:`、`series and ...`、`return series or default`。
    教训泛化：**公共件的入参要按"最脏的可能"来防御**（Series / list / None 都当输入），
    因为在页面里测不出来 —— 一接线才暴露。
19. **【v6.12 · 跨模块共享的"键"必须有规范化函数】**：周期在全 app 有三种写法 ——
    数据层 `'D'/'W'/'M'`、UI 中文 `日线/周线`、存储 `daily/weekly`。
    若各处自己拼字符串，就会出现"日线画的线跑到周线上""同一只票的标注读不出来"这类
    **静默串档**（数据没坏、界面上就是少了东西，最难查）。
    解法：`data/annotations.period_key()` 一个入口兜住**所有**写法，
    调用方（页面/图层）只管传自己那套；**禁止绕过它直接拼**。
    同类需要"规范化入口"的键：symbol（`watchlist_store.normalize_symbol`，大小写/空白）、
    日期（`annotations.normalize_date`）。新增任何跨模块键，先给它写一个 `normalize_*`。
20. **【v6.12 · 离屏 GUI 脚本的三条打桩铁律】"脚本看起来卡死、毫无输出"几乎总是这三件事**
    （本轮真实发生，用户以为是 VPN/网络问题，其实与网络无关）：
    - ① **模态框必须打桩**：`QMessageBox.*` / `QInputDialog.getText` 在离屏环境
      **没有用户可点 ⇒ 永久阻塞**。一条"浏览模式下点添加应给提示"的断言就足以让整个脚本挂死。
      做法：在脚本开头把 4 个 `QMessageBox` 静态方法 + `QInputDialog.getText` 换成
      "记录一下立刻返回"，并**把弹出的内容当断言素材**（比弹窗本身更有价值）。
    - ② **测试不碰网络**：主窗口构造会起 `UpdateCheckerThread`（请求 GitHub）。
      做法：构造窗口**之前**把 `ui.main_window.UpdateCheckerThread` 换成空实现
      （带一个 `update_available.connect()` 的哑信号）。测试不该依赖网络，也不该被网络拖慢。
    - ③ **结尾必须 `os._exit()`**：只要还有**非守护 QThread** 存活，解释器就不退出；
      而 `| Select-Object -Last N` / `| tail -n N` 会**缓冲到进程结束**才显示 ——
      于是"断言全过了"也表现为"长时间无响应"。做法：`sys.stdout.flush()` 后 `os._exit(code)`。
21. **【v6.15 · `ViewBox.setYRange` 会偷偷加自己的 padding】"y 怎么总比预期宽一点"**（真实踩到）：
   `view_box.setYRange(lo, hi)` 之后 `viewRange()` 拿到的**不是** `(lo, hi)` ——
   pyqtgraph 会在此基础上**再叠一层它自己的 defaultPadding**（实测 ≈2%~4.7%，还随
   `autoPadding` 状态漂移；同一次调用先后顺序不同，幅宽能差出 0.2%）。

   断言没法写、调参也调不准（本次写 §7-B4 断言时当场撞上：期望 99.4~110.6，实测 98.77~111.23）。
   解法：**量程一律 `setYRange(lo, hi, padding=0)`**，把 padding 完全掌控在自己手里

    → **自检口诀**：离屏脚本"无输出"时，先怀疑**模态框**、再怀疑**残留线程**，
      **最后才怀疑业务代码**（尤其别一上来就怪网络/VPN）。

     23. **【v6.18 · 复用公共工厂时，"写死的默认值"会咬人】**（用户实测倒逼）：
     `ui/views/backtest.py._risk_spin` 是回测页数值控件的**公共工厂**，里面把步长写死成
     `1 if decimals == 0 else 0.5` —— 对 1 位小数的百分比控件没问题，但新加的 **2 位小数**
     控件（成交模型的「买卖价要多等」，范围 0.01~0.20）**按一次上箭头就 +0.5 → 被上限夹住**。
     用户原话：「**直接跳到 0.2 并且无法继续上调，没有过度价格**」（差点被当成"图标坏了"）。
     **修法**：步长随 `decimals` 自适应（`0 → 1` / `1 → 0.5` / `≥2 → 10^-decimals`），
     并把上限由 0.20 放宽到 **1.00 元**（高价股的绝对价差也放得下）。
     **教训泛化**：公共工厂里的"经验默认值"一旦被用在**新的量纲**上就可能荒谬 ——
     新增一类控件时，把工厂里**每一个 `setXxx` 的隐含假设**都读一遍；
     数值控件**必须能逐级调节**，"一按就顶到边界"用户会直接判定为坏了。
     （断言：`singleStep` 随小数位自适应 + 连续 `stepUp` 逐级过渡 + 下限按到底不越界。）
24. **【v6.18 · 一次性探针的 `check(说明, 条件)` 参数顺序写反 = 全部断言形同虚设】**
    （本轮真实踩到，靠"**输出里说明文字变成了 `True`**"抓到）：探针里把 helper 定义成
    `def check(cond, desc)`，而所有调用处都是 `check(说明, 条件)` —— 于是**条件参数收到了一个
    恒真的字符串**，全部 `[OK]`，看上去"18 项全过"，实际什么都没验证。
    **三条纪律**：
    ① 探针的 `check()` 一律与仓库两个冒烟脚本保持**同一签名 `(desc, cond)`**，别自创顺序；
    ② **看输出**：断言说明必须是**人话**；一旦打印出 `[OK] True` 就说明参数顺序错了；
    ③ **凡"一次全过"都要警惕**：先挑一条**故意会失败**的条件跑一遍（或在心里过一遍
      "这条要怎样才能失败"），确认它不是恒真 —— 这与 §11.5-2 的"负向对照"是同一种疫苗。
 25. **【1.22 · `isVisibleTo(ancestor)` 的口径 = "只看到 ancestor 为止"】**（1.22 断言被误改的根源）：
     `w.isVisibleTo(a)` 只检查 `w` 自身与**到 a 为止（含 a）**的祖先是否被显式隐藏；
     **a 之上**的祖先是否隐藏**不影响**结果。所以当控件被"默认收起"的卡片包住时：
     `box.isVisibleTo(view)` 会变成 False（卡片隐藏了），而 `box.isVisibleTo(pane)` 仍准确
     反映"这一行按条件该不该出现"。
     **纪律**：断言"某控件按条件显隐"时，ancestor 取**它所属的卡片**，别图省事用页面 ——
     否则版式一改（收纳/折叠）断言就假失败。附带好处：这样写**不必为了断言去展开卡片**

     先踩到的坑：把配置区做成"就地展开"、塞进 `QVBoxLayout(stretch=0)` 时，
     `QScrollArea(widgetResizable=True)` 拿到的却是一个**与内容无关的极小高度**
     （函数卡片只剩两行可编辑）——**布局自动分配不可依赖**，必须显式定量。
     **最终定稿**（用户实测拍板"就地展开不好看"，见 §10-14 L3）：改**覆盖层**。
     两条纪律：
     ① **覆盖层不进布局** ⇒ 主区（结果区）高度**全程不变**（实测打开抽屉前后都是 625px；
        就地展开时会掉到 475/276）——"不挤主区"由此变成结构性保证，而不是靠调参；

     并且必须显式定量。
 27. **【1.22 · 页内覆盖层的两个必踩坑 —— 都靠用户截图才发现】**（回测页胶囊抽屉，真实踩到）：
     ① **同级 widget 的层叠顺序 = 创建顺序**：遮罩若建在结果区**之前**，后建的结果区
        （KPI 卡 / 成交明细表 / 图表）就会整体压在遮罩**之上** —— 用户看到的原话是
        "**遮罩遇到表格根本盖不掉，显得非常丑**"。
        修法：**覆盖层（遮罩 + 抽屉）放在 `_setup_ui` 的最后创建**，打开时再 `raise_()` 兜底；
        自检办法：`page.children().index(scrim)` 之后的 QWidget 数必须为 **0**。
     ② **`QStackedWidget` 会把页面拉满，从而撑散页面内部的伸缩布局**：五张配置卡片直接

        修法：给每页套一层容器 `QVBoxLayout(holder)` → `addWidget(pane)` + **`addStretch()`**，
        让卡片按自身 `sizeHint` **贴顶**（实测卡片高度从 ~100% 降到 19%）。
     **通用判据**：**"浮在内容上"的东西，既要管层级（创建顺序/raise），也要管容器是否会拉满它。**
28. **【v6.24 · `AxisItem.setWidth()` 不会立刻生效 —— 断言必须先转一圈事件循环】**（R8 施工真实踩到）：
    `setWidth(w)` 只做两件事：`self.fixedWidth = w` + `self._updateWidth()`；
    而 **`width()` 要等下一轮布局**（`processEvents()`）才反映新值
    （实测：设完立刻读 = 旧值；`processEvents()` 后 = 新值）。
    这一个 API 行为会同时制造**两种假结果**：
    · **假失败** —— 设完立刻断言 ⇒ 读到旧值 ⇒ 明明修好了却报红；
    · **空过（更危险）** —— 在 `show()` 之前读 ⇒ 所有轴都还是默认 35.0 ⇒
      "各轴宽度全都相等"这种断言**会莫名通过**（本轮真写出过一条这样的**假绿**）。
    **纪律**：凡"设置 + 立刻断言"的图形 API，先确认它要不要一次事件循环；
    对**不变量类**断言（相等 / 幂等 / 单调），**先证明"改前不成立"（复现），再证明"改后成立"** ——
    否则你并不知道自己测的是"修好了"还是"压根没测到"。同族：第 21 条（`setYRange` 偷加 padding）。

30. **【v6.24 · `FlowLayout` 的换行高度会沿父链"静默失效" ⇒ 宿主必须直接钉 `minimumHeight`】**

    链条上任何一环不转发就**静默失效**：不报错、不警告，只是**第二行被裁掉**
    （实测表现："分组胶囊只剩上半截"）。`QWidget` 默认 `hasHeightForWidth() = False`
    就是这个链条最常断的一环。
    **正确做法 = 双保险**：① `FlowHost(QWidget)` 覆写 `heightForWidth()` 透出去（父链配合时走优雅路径）；
    ② **`sync_height()` 按当前宽度算出所需高度直接 `setMinimumHeight`** ——
    这条**不依赖父链配合**，是真正兜底的；且要在"重建子控件之后"与 `resizeEvent` 里**各调一次**
    （宽度变了换行数就变）。
    **通用判据**：**凡"要我算高度"的自定义布局，都别指望父链替你传 —— 直接把结果钉进自己的最小尺寸。**
    同族：第 28 条（设置后要转一圈事件循环）、第 27 条（容器会把"浮在内容上"的东西拉满）。

48. **【v6.27 · "看不见" = "画不出来"：依赖视图的角度类工具不能用"屏幕 45°"】**（用户实测）

    并且**上下各 4 条**（上 = 未来压力、下 = 未来支撑 —— 用户点名的用途就是"未来支撑位"）。
    **通用判据**：依赖视图的几何工具，"基准"要选**画面上看得见的量**（可视区间），

    同理：甘氏扇形按标准做法**只需一个起点**（角度由视图比例定）。
    **通用判据**：加/改一种画线类型时，先问"它在真实交易里回答什么问题"，
    再决定它该画成线段 / 射线 / 无限直线 —— 别照着"两根手柄"这种实现细节定语义。

50. **【v6.28 · pyqtgraph 的点击/拖动事件是"**二选一**"：接受了 press 就拿不到 click/drag】**
    框架原文："**If no item accepts the mousePressEvent, then the scene will begin delivering
    mouseDrag and/or mouseClick events.**"⇒ 图元里 **`accept()` 了 press**，那两类事件**永远不会来**；
    而 Qt 自己的 `mouseMoveEvent` / `mouseReleaseEvent` **照常投给"鼠标抓取者"**（探针实测：
    日志里 `press / move / release` 都有，`click / drag` 一个都没有）。
    ⇒ **自定义可拖图元的正确写法**：press 里记下起点并 `accept()`（成为抓取者）→
    `mouseMoveEvent` 里按位移 `setPos` → `mouseReleaseEvent` 里判定
    "**没移动 = 点击（选中）/ 移动过 = 拖动（落盘）**"。
    三个必踩细节：① 位移要**换算到父坐标系**（`parent.mapFromScene`）再 `setPos`，
    否则缩得越狠飘得越远；② "算不算拖动"的阈值必须用**像素/场景坐标**，用数据坐标会时灵时不灵
    （y 量程 0~1 的图上 20 像素只有 0.02，被当成"没动"）；③ `pg.TextItem` 天生
    **不开 hover**（`acceptHoverEvents()==False`），别指望 `hoverEvent` 里 `acceptDrags` 能救。
51. **【v6.28 · "能画出来"≠"能选中"：ROI 家族的三处点击黑洞】**
    管线 B 要"点线选中 ⇒ 逐个删除"，但：**(a)** `pg.ROI` 默认 `acceptedMouseButtons()` =
    **`NoButton`**，而它的 `mouseClickEvent` 是 `elif self.acceptedMouseButtons() & ev.button():`
    ⇒ **`sigClicked` 永不发**（设成 LeftButton 才通）；**(b)** `PolyLineROI` 的每段线是
    **子图元**（`LineSegmentROI`），点线段不走父 ROI 的信号；**(c)** 附属图元
    （斐波档位线 / 扇形射线 / 标签）**从来没人给它们挂点击**。
    **终解**：别指望"每个图元都自觉发信号"，在交互层做**统一拾取**

52. **【v6.28 · "用户无法调整"是**设计缺陷**，不是 bug —— 没给输入口 = 只能靠程序猜】**
    甘氏扇形原来是"**一个起点 + 视角决定角度**"：程序只能在"屏幕 45°"和"可视区间对角线"
    之间猜（v6.27 两版就是这两种猜法），用户对方向/陡缓**没有任何输入口** ⇒
    表现就是用户说的"**会自动生成一个上下对称的样式用户无法调整**"。
    **修法**：改**两点**（起点 + 参考点；参考线 = 1×1）—— 把"程序猜的量"变成"用户画出来的量"，
    方向（上=压力 / 下=支撑）与陡缓全由第二点定，落库后随时可拖。
    **通用判据**：当一个工具需要某个**软件根本不知道的领域量**（甘氏 1×1 的"每点价值/时间周期"）
    时，**别替用户猜，给用户一个输入口**；"猜"出来的默认值看起来完整，实则不可用。
53. **【v6.29 · "算出来的主图元"两条专属坑：不夹区间会外推、刚进场景回读会拿到过期坐标】**

    **② 刚 addItem 就回读 = 读过期坐标**：落库后想"立刻按画出来的样子回写"，于是调

    **通用判据**：① 凡是"由外部数据算出来的几何量"，**边界必须先夹**（用户能拖到窗口外）；
    ② 落库那一刻要"按画面回写"时，**宁可纯计算，也别去读刚创建的图元**

60. **【v6.36 · 取消一个长任务：宁可抛异常，也不要"返回部分结果"】**
    横截面扫描可以取消。最省事的写法是"发现取消就 `break`，把已算完的那部分返回" —— 但返回的是
    一个**半个矩阵**：命中家数、广度占比、有效样本数**全都是错的**，而界面上**看不出任何异常**
    （跟"真的就这么多"长得一模一样）；更糟的是它会进会话缓存，之后"切日期"看到的就一直是这个半成品。
    **修法**：定义 `ScanCancelled` 并在**块边界抛出去** ⇒ 调用方在**类型层面**就没法把半成品当成品；
    缓存**只落成功的结果**；线程回 `finished(job, None)` 明确表示"没有结果"。
    **通用判据**：凡是"可取消的长计算"，问一句"**取消后我手里这个东西，会不会被下游当成完整结果？**"
    —— 会，就别返回它，**抛异常**。（同理：分页 / 流式接口要**显式**标 `partial=True`，不能只靠长度判断。）
    同批把"发起新任务 ⇒ 旧回包作废"收成公共件 `JobGuard`：**这类判据每页各写一遍，
    迟早有一处忘了比 token**，而症状是"旧结果覆盖新结果"且界面看着完全正常（§11.5-11）。
61. **【v6.37 · 离屏冒烟里 `isVisible()` 恒 False —— 先把页面切到前台再断言】**
    在 `smoke_pages_overlay` 里断言 M2 页的抽屉"可见"，怎么改都是 False：控件明明 `show()` 了。
    原因：**`isVisible()` 是"自己可见 **且** 所有祖先可见"**—— 该页挂在 `QTabWidget` 的
    **非当前页签**上，祖先整条链是 hidden ⇒ 子控件永远 False（`isHidden()` 才只看自己）。
    **修法**：像真实用户那样先切过去 —— `main_win.switch_to('backtest')` +
    `tabs.setCurrentIndex(该页签)` + `app.processEvents()`，再断言。
    **通用判据**：**断言"看得见/看不见"之前，先让"从入口到该控件"的整条链都处于用户会走到的状态**；
    想只测控件自身就用 `isHidden()`，想测用户视角就用 `isVisible()`（两者别混用）。
62. **【v6.40 · 同一个"指数代码"有两套形态 —— 复用键之前必须在边界规范化】**
    用户实测 M2/M3 选"沪深300"，每次都"接口未返回成分股"；但批量预下载弹窗同样的功能一直是好的。
    根因：本项目并存**两套指数代码约定** —— 指数**日线**接口要带市场前缀（`sh000300`，
    新浪 `stock_zh_index_daily`），而成分股三接口（akshare `index_stock_cons*`）只要
    **6 位纯数字**（`000300`）。M2/M3 的指数下拉**复用了** `INDEX_PRESETS`（日线用）的带前缀键
    直接透传 ⇒ 带前缀喂给成分股接口：新浪源返回 None（`'NoneType' object has no attribute 'find'`）、
    中证源下载到错误页（`Excel file format cannot be determined`）⇒ 三个候选全失败。
    **实锤方法**：同一时刻同一接口，`'sh000300'` 返回 0 只、`'000300'` 返回 288 只 ——
    **先分清"代码格式"还是"接口挂了"，别急着怪网络**。
    **修法**：`akshare_feed.normalize_cons_code()`（带前缀→裸码，坏码原样返回）收在**行情源边界**
    一处，`fetch_index_constituents` 先规范化 + 格式不对快速失败（不空跑三个接口）；调用方零改动。
    **通用判据**：**"长得像同一个东西"的键在跨模块复用前，先问"两个下游要的格式真的一样吗"** ——
    复用下拉/预设时尤其危险（复用的那一刻就绑定了上游的格式约定）；
    规范化函数放**消费方边界**（谁要求什么格式谁负责收口），并配一条"格式不对就快速失败 + 说人话"的护栏。
63. **【v6.41 · 异步回包分支必须装配与同步分支"同样的状态"；内核的警告必须有 UI 出口】**
    用户实测 M2「指数成分」扫描成功但**名称列全空**。根因有两层，第二层更值得记住：
    ① `resolve_scope` 的三个分支各自装配页面状态 —— 自选装 `names_map()`、全A 装 `roster_names()`，
    唯独**指数成分走异步回包**（`_on_constituents`），写的人只回填了 `_symbols` 漏了 `_names` ⇒
    名称列空 + **「剔除 ST / 退市」整轮静默失效**（内核拿不到名称就没法剔 ST）。
    ② 内核对这种口径残缺**其实出过警告**（`scan()` 的 warnings："未提供花名册名称…未生效"），
    但 UI 的 `_on_finished` 把 warnings **整个吞掉** ⇒ 坏结果看起来完全正常（§10-4 的"静默"教科书案例）。
    **修法**：回包补装配（与同步分支同源 `roster_names()`）+ 两页 `_on_finished` 给警告出口
    （回执 ⚠ 摘要 + tooltip 全文）+ 顺手堵上 readiness 回包覆盖扫描回执的同类洞。
    **通用判据**：**同一页面的多个数据来源分支，逐个对照"它们各自装配了哪些页面状态"** ——
    异步分支最容易漏（写的时候只想着"把结果拿来"）；**内核出过声的东西，UI 必须有对应的耳朵**；
    否则等于没出声。
64. **【v6.43 · `adaptive_axis` 的契约是 bar 序号轴 —— 给 epoch 秒轴喂 `attach_all`，y 跟随会 100% 静默失效】**
    M3 第一版用 `ChartHost(date_axis=True)`（x=epoch 秒）又把 epoch 数组喂给 `attach_all` ——
    而 `adaptive_axis` 模块头明写"x 一律假定 bar 序号；epoch 秒的 DateAxisItem 轴不适用本模块"。
    后果链：provider 收到 1.7e9 当"序号" ⇒ 切片恒空 ⇒ 两个窗格的 y 跟随从未执行（指数副图
    退化成"对全历史自动量程"：2000~6000 轴压扁 4000 点跨度）；底部刻度钉在"序号 729"而轴是
    epoch ⇒ 视野外 ⇒ 整根 x 轴没有日期标签。用户原话："我明明在行情页优化了半天搞了个可用的图表，
    这里又是一塌糊涂"。
    **为什么冒烟没抓到**：断言只验了"跟随器挂上了 / x 联动了"，从没验"缩放后 y 数值范围真的跟随" ——
    **"挂了"≠"生效"**。
    **修法**：`breadth_chart` 改回 bar 序号轴（与全 app 同一套已验证口径），指数 df 按日精确对齐
    到广度轴后只画当前区间；冒烟补上"缩放后 y_range 数值 == 可视切片极值 ±padding"与"刻度落在
    视野内"两条硬断言。
    **通用判据**：复用公共件前先读它的**模块头契约**（它写"不适用"就是在等你踩）；给公共件写断言时，
    断言必须落在**输出数值**上，不是落在"接线完成"上。
65. **【v6.43 · 按文件读数时"本地没文件"的标的会被静默跳过 —— 差集必须交给内核记「数据不足」】**
    用户实测：选沪深300（当时名单 288 只）扫描后回执只报"扫描 27 只"，**没有任何解释** ——
    因为 `read_daily` 按文件读时 `if not os.path.exists(path): continue` 直接跳过缺文件的 261 只，
    内核从头到尾没见过它们：不进总数、不进三态、不进 warnings。
    同一问题的另一面：`scan()` 的"读数为空 ⇒ 提前返回"路径会把整份 missing 名单吞掉回**全空白**
    （用户："不补齐直接扫就返回空白，无论 M2 还是 M3"）。
    **修法**：`scan_lake` 算差集交给 `scan(missing=…)` ⇒ 逐只记 INSUFFICIENT（"本地没有日线文件"）
    进 `counts.total` 与 warnings；早退路径同样落名单（界面永远有东西可看）；`status_on` 切片补上
    missing（切日期数字不跳变）；`ScanOutcome.status_on` 在无矩阵时兜底基准日（注意 NaT/None 都要接住）。
    **通用判据**：**"名单 → 读数"的每一步都要能回答"我要的 N 只去哪了"** —— 任何 `continue`
    式的静默丢弃都必须变成三态里的一个桶；"结果比预期少"不报错 = 最阴的静默错值。
66. **【v6.43 · 异步回包的"早退守卫"不能连占位文案一起跳过 —— "正在体检…"会永远挂在那里】**
    用户实测：500 只的体检"跑了三分钟还是同一个界面" —— 体检本体只读 footer（毫秒级），真因是
    `ReadinessFlow._on_probed` 在"已有扫描结果"时**直接 return**：守卫防的是"覆盖扫描回执"，
    但它连"把正在体检…换成真话"也一起挡了 ⇒ 占位文案永久冻结，用户以为软件卡死。
    **修法**：守卫只拦"回执区写入"；占位文案（`lbl_empty` 含"正在体检"）无论结果在不在都要更新
    （进度时更新一次、回包时换成真话）；扫描侧同理：`shift_date` 无轴时的提示要说出"为什么没轴"。
    **通用判据**：写"早退守卫"时逐个检查被它挡住的副作用 —— **"不许写 A"不等于"连 B 也不写"**；
    任何"进行中"文案都必须有"无论发生什么都会被替换"的兜底，否则就是谎言。
67. **【v6.43 · 拖动调布局必须用"按下瞬间锁定的参考系" —— 拿实时几何反推 = 布局回流正反馈振荡】**
    分界线拖动第一版：每个 mousemove 都重读当前交界几何算比例 f 再改 stretch ——
    改 stretch → 布局回流 → 边界搬家 → 下一帧对着**新边界**算 ⇒ 正反馈振荡，
    用户手感就是"只能拖一小段就丢失拖把 / 往上拖根本没反应"。
    **修法**：按下瞬间锁定 `(start_y, span, start_f)`，拖动只叠加相对位移
    （`f = start_f + (y-start_y)/span`）—— 边界怎么搬家都影响不到参考系，上下双向线性跟手。
    **通用判据**：凡"拖动中会改变你所依据的几何"的交互（分栏/缩放手柄/滚动条），必须用
    **按下时快照**做增量计算，绝不能用实时几何反推绝对位置。
    附带两课：① 功能设施要**看得见**（隐形热区 = 没有这个功能）；② PyQt6 的
    `QGraphicsView.mapFromScene(QRectF)` 返回 **QPolygon** 不是 QRect —— 只能逐点映射。
68. **【v6.43 · 数据源选列靠"含某字的第一个列"= 定时炸弹；测试打桩必须带与线上一致的列结构】**
    成分股接口换序到官网优先后，用户实测"沪深300 名单只剩 1 只：000300" ——
    官网 df 同时有「指数代码」和「成分券代码」两列，而选列逻辑是"第一个含'代码'的列"，
    恰好命中「指数代码」⇒ 把指数自己当成唯一成分。旧接口（同花顺，列名「品种代码」）从没暴露；
    而冒烟打桩只放了「成分券代码」一列 ⇒ 假绿。
    **修法**：选列改为**权威列名白名单**（成分券代码/品种代码/…）+ 兜底"含代码但不含指数"；
    打桩升级成与线上同构的列集合，加"名单里绝不允许出现 000300"的回归钉。
    **通用判据**：对第三方数据源的列名匹配要么**精确白名单**要么**带排除词的兜底**，
    "第一个包含关键字的列"在源升级时会静默拿错列；**打桩的列结构必须抄线上**（少一列 = 少一条回归保护）。
69. **【v6.43 · `QHeaderView.ResizeToContents` × 大表逐格 setItem = 平方级冻死 UI】**
    用户实测"点一下日期箭头软件大概率卡死" —— M2 结果表 6 列设了 `ResizeToContents`（动态测宽），
    全 A 5400 行 × 7 列 ≈ 3.8 万次 setItem，**每插一格都触发全表重新测量** ⇒ O(n²) 冻死 UI 线程；
    每个 item 还 setToolTip（再叠一层开销）。
    **修法（填表三件套）**：`setUpdatesEnabled(False)` → 逐格填（tooltip 只给必要列）→
    列宽 Interactive + 填完**一次性** `resizeColumnsToContents()` → 开更新；超 2000 行截断并在
    脚注说实话（"仅显示前 N 行，共 M 行"）；冒烟钉住"列宽模式不是 ResizeToContents"。
    **通用判据**：QTableView 类"动态"模式（ResizeToContents / 自动排序 / 逐格插删）在 >几百行时
    都是性能陷阱；批量写入的铁律 = 关更新 → 填 → 一次性收尾。
70. **【v6.44 · 新增“记住上次”类偏好键：构造期从真实 preferences 泄入 → 冲乱默认顺序断言，且冒烟误写真实库】**
    给 `desk_ui` 加了 `sub_order`（副图换序持久化）后，`smoke_pages_overlay` 早期“窗格顺序 =
    main/vol/macd/sub1/sub2”等**假设默认顺序**的断言突然变红。根因：`Preferences` 单例在脚本
    把 `path` 重定向到临时目录**之前**、于 `import` 时已从**真实** `~/.jian_data/preferences.json`
    把 `desk_ui` 载入内存；窗口一构造就读到用户真机存的 `sub_order` ⇒ 渲染顺序被改。更糟的一次：
    把“抹平用户态”的 `preferences.set(...)` 误放在重定向/stub **之前** ⇒ 那次 `set` 触发真实
    `save()` 把整份偏好写回了磁盘（污染用户库 + 顺手抹掉了用户真机换序）。
    **修法**：冒烟脚本必须先重定向 `path` + stub `Preferences.save`，**之后**再在内存里把会影响
    构造的用户态（`sub_order`、breadth 的 ratio/chart/overlay/index_style 等）抹平，让窗口以默认序起来；
    顺序敏感断言不得依赖用户偏好（与 §11.6 breadth overlay/index_style 隔日误报同族）。
    **通用判据**：凡是 app 新增“记住上次”类偏好键，都要问一句“冒烟会不会在构造期把它从真实库读进来、
    或把它写回真实库”；防污染重定向要**早于任何 `set`**，且只给 `Preferences.save` 挨桩不足以挡住
    “import 时已载入的真实值”——需显式在内存抹平。

- **11.5-71** 【v6.46 · §7-B10-M1】三坑同体：① **回测静默截断** —— 本地日线滞后时 `BacktestEngine` 会把 `data<=end_date` 截到旧末日而不告知 ⇒ 默认终点必须走日历算“最近已定稿交易日”且回测前滞后自动补、补不到**回退+回执**（`_apply_end_date_receipt`，只回退不前移）；② **构页自启的 QThread Worker 会在离屏冒烟里真联网 + 写真实目录** ⇒ 测前必须把 `CalendarWorker` 打桩为不 `start`（并发到 `~/.jian_data/trade_calendar.json`，防污染自检名单要加）；③ **冒烟脚本里同名模块别名（`_bflow`）会被后续段落重新绑定成别的模块**（breadth_flow）⇒ 给新模块用**唯一别名**，否则 monkeypatch 打到错的模块、真线程偷偷跑起来
