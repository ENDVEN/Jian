- **11.5-73** 【v6.47 · 窄屏不撑窗（用户明令）】工具栏/摘要条的**单行 QLabel 绝不能塞长文本**——`QLabel` 不包字时 `minimumSizeHint` = 整串宽度，会把窗口**最小宽度**顶大，窄屏/小屏直接铺不开。做法：**单行标签只留短状态 + 一个“⚠”短标记，长说明进 tooltip 或结果区（`lbl_empty` 已 wordWrap，可换行）**；并给这类单行标签设 `setSizePolicy(QSizePolicy.Ignored, Preferred)` 使其**可缩不撑窗**（已用于 M2/M3 `lbl_receipt` 与 M1 `lbl_range_note`）。新加任何顶部回执都遵此模式。
- **11.5-85** 【v1.43 收口二次 · 流程】`design/` 样板是**验收标准，不是示意图**：样板里的形态
  （浮层 vs 独立窗口 / 状态胶囊 / 迷你进度条 / 每行操作 / 三态配色）必须**逐条变成本批的验收项**，
  否则"照样板做"会写成"用现成控件拼一个能用的" —— 用户一眼就看出"跟样板完全是两回事"。
- **11.5-88** 【v1.46 · 体验】**"临时占位"必须有一个"能把它换回来的主人"**：
  ① **先问"我要改的区域，当前在显示什么？"** —— 给结果区 `set_empty("更新中…")`（内含
     `empty_box.show() + table.hide()`）会**盖掉已有结果**；而回包后的渲染分支若只认"正在体检"
     这一种占位（`if '正在体检' in lbl_empty.text()`），那句"更新中…"就**永远换不回来**
     ⇒ 页面永久卡住（用户实测：下载早已完成、KPI 还是旧的、结果区停在"更新中…"）。
  ② **正解 = 入口侧判状态**：**有结果就不碰结果区**（结果区归结果、进度归回执/进度条/下载条）；
     无结果时才用占位，回包后由体检渲染换成就绪度摘要。
  ③ 通用判据：任何"临时占位"都要同时具备**写入点**与**清除点**，判据是**内容**而非**状态位**
     —— 状态位（`_syncing`/`_busy`）收尾后会失真，文案不会。
  ④ **"用户看不懂的数字"要给看得见的第一手解释**：`partial`（历史不足）旧版只给一个数字 ⇒ 用户
     只会反复点更新去追一个**永远追不上**的数（次新股，数据源本就没有更早行情）；必须点名 + 说明
     "补不齐、不是缺陷" + 给出路（调小门槛）—— **只给 tooltip 不算解释**（§10-10）。
- **11.5-89** 【v1.46 · 结构】**"形状不同"的东西不要塞进同一个壳 —— 否则加一种就漏一处**：
  M2/M3 = 某日横截面 / 逐日广度，M1 = 一段时间的逐笔与净值；硬套 M1 的壳（同批列位换表头 + 同一套
  "累计/胜率/成交"胶囊 + 同一块净值图）⇒ 散出 **6 处 `if kind`** + 一块永远画不出的空白图。
  **正解 = 声明式注册表**（列 / 过滤轴 / 动作集一行一种 kind）。同批另四课：**别让两种语义共用同一批键**
  （M2 命中数塞进 `total_trades` ⇒ 静默错值）· 自定义布局必须**跳过隐藏子件**（手写 `FlowLayout` 漏
  `isEmpty()` 会占位）· "按状态显隐按钮"**不是守卫**（入口须自校验 kind）· 异步解析（指数名单）+ 立刻
  执行 = 必然空跑（须"置待跑标记 + 等名单与体检就绪"）。→ 详情见 `docs/history/README.md` §8（v6.63 条）。
- **11.5-92** 【v6.66 · 入口】**"功能是好的"≠"用户能用上" —— 空容器必须自带入口**：
  数据层与取数全对（探针实测：不复权真能下、真能落盘、真能渲染），用户的结论却是"复权坏了" ——
  因为 **① 批量下载没有口径选择**（那个分区永远轮不到）、**② 空分区没有下载入口**
  （表里没行可勾 ⇒ 按钮恒灰 ⇒ 死局）。**口径**：新增一种"独立存储"（分区 / 口径 / 格式）时，
  必须同时回答两件事 —— **谁来写它**（批量入口认不认它）、**空的时候怎么起步**（空态有没有入口）。
  ⚠ 语言级坑：`str.isalnum()` **对中文为 True** ⇒ 拿"像不像代码"当判据必须加 `isascii()`。
- **11.5-96** 【v6.68 · UI】**"程序入口能过、真人点不动" = 组件把"合法假值 key"当无效吞掉**：
  `SegmentedControl._on_clicked` 曾用 `not key` 判无效，而**「不复权」的业务值 `ADJUST_NONE` 就是
  空字符串** ⇒ 手点被静默丢弃（状态与高亮都不动）；`set_current()` 没这判断 ⇒ 程序化正常 ⇒
  **断言全绿、真人点不动**。**口径**：① 组件判"无效/缺失"**只许用索引 / `in` / `is None`，绝不用
  真值判断**（`if not x` 会吞 `""`/`0` 这类**合法**值）；② 手点是主入口的控件，断言**必须含一次真实
  点击**（`buttons()[i].click()`）。
- **11.5-108** 【v6.79 · Qt 布局】**一个 widget 只容一个布局，第二个会被"静默丢弃"**：
  `ui/views/formula_hub.py` 先 `QVBoxLayout(self)`，随后 `hub_layout.HubLayout(page)` 又
  `QHBoxLayout(page)` —— 控制台只有一行 `QLayout: Attempting to add QLayout "" to FormulaHubView "",
  which already has a layout`，**没有任何异常**，但左右两栏（列表 + 详情/编辑器）**从未挂到页面上**
  ⇒ 用户看到的"页面只剩标题一行"就是这么来的。
  **口径**：① 页面自己只建**一个**根布局；② 版式模块（`*_layout.py`）**只造容器**（`self.root = QWidget()`
  + 自己的 `QHBoxLayout(self.root)`），由页面 `root.addWidget(layout.root, 1)` 挂进去 —— 这就是
  `scan_view` 三件套的既有范式；③ 新增"XX 页"时先抄范式，别自己另起布局。
  **识别信号**：Qt 打印 `QLayout: Attempting to add ... which already has a layout` 时，
  九成是"两个模块都往同一个 widget 上 `QLayout(widget)`"，**不是**样式或数据问题。

- **11.5-111** 【v6.86 · §7-B15 视觉返工】**"折叠态"必须自带展开出口；定宽分栏别交给 QSplitter**：
  参数研究页第一版四个视觉/结构事故，全部是"没照设计稿施工"的代价（§11.5-85：样板是验收标准）：
  ① **展开钮长在被折叠隐藏的容器里 = 死胡同**：左栏收起后连「»」都消失，重启后
  `sweep_ui.panel_collapsed=True` 还原 ⇒ 整页只剩结果区，功能不可用。修法照设计稿
  `.panel.collapsed .strip`：**折叠态 = 46px 竖条，展开钮/竖排标题长在竖条上**；
  冒烟加"真点击折叠 → 展开钮可见 → 真点击展开"的回归断言。
  ② **分栏宽度交给 QSplitter 会在真实 DPI 下塌 0**：`setSizes([340,760])` 在 show 前设了也
  会被子件的 minimumSizeHint/布局博弈吃掉（离屏看是好的、真机没左栏）。修法：设计稿本就是
  "306px **定宽** + 右栏吃满" ⇒ 根本不该用 splitter，直接 QHBoxLayout + setFixedWidth(306)。
  ③ **同一个按钮在两处 connect 同一个 toggle = 双触发互相抵消**（form 内部连一次、view 又连
  一次 ⇒ 点一下等于点两下）。修法：控件自持连接 + 发 `collapse_changed(bool)`，视图只订阅。
  ④ **306px 定宽面板里不许出现横向滚动条**：网格行三枚 spinbox + 四格日期把 minimumSizeHint
  撑到 694px。修法 = 日期/下拉/图表一律 `QSizePolicy.Ignored`（横向可缩）+ 滚动区横向
  `ScrollBarAlwaysOff`；数值控件仍守 72px 最小宽（§10-9）。
  **v2 返工再抓三笔（同族，用户第二张截图）**：⑤ 视图根布局 `addWidget(form)` 后又
  `addStretch(1)` —— stretch 与结果区(stretch=1) **1:1 平分剩余宽度** ⇒ 右栏被挤成半宽、
  中间一大块空白（定宽项旁边**不许**再放裸 stretch）；⑥ `QHBoxLayout(chart_body)` 已把
  row 布局挂上父级，再 `cl.addLayout(row)` = `QLayout::addChildLayout: already has a parent`
  **静默丢弃**（§11.5-108 同族）；⑦ 面板自身在 `root.addWidget(panel)` 不给 stretch 会被
  自家兄弟 stretch 压成矮条（定宽的是**宽度**，高度仍要 stretch 1 吃满）。
  另两笔同批小坑：**图例别在 paintEvent 里画字形**（■ 依赖字体回退，缺字就是乱码方块 ——
  用 QLabel 底色 chip）；**没数据的图表要藏起来**（pyqtgraph 空图也是一根裸坐标轴，
  空态给占位卡）。**排查动作**：做完折叠类 UI 必须离屏截图三种状态（展开/折叠/有数据）
  人眼各看一遍，再加"真点击"断言 —— `isVisibleTo` 只能证明"没被显式隐藏"，
  证明不了"用户找得到出口"。

- **11.5-114** 【★1.66 · 全站竖向布局】**没有最小高的那个控件，会替你承担所有亏空**：
  **症状**：右栏"第一次正常，第二次被压成一条"（用户实测：改参数二次测试后结果图极端压缩）。
  **真因**：一列里 KPI 行 / 时间轴 / 结论条 / 候选表都有最小高，**只有 pyqtgraph 图卡没有** ⇒
  竖向少几十像素时，Qt 只能压它 ⇒ 图被压扁、坐标轴重叠。
  **修法**：① 给弹性项设**硬底线**（`setMinimumHeight`）；② 余量**显式**给主角（`addWidget(w, 1)`）；
  ③ 亏空交给**滚动区**（右栏本来就该可滚）。**判据**：按目标窗口尺寸实测关键件高度（冒烟钉住）。

- **11.5-116** 【★R4-b】**"照设计稿做"不是"凭理解重画"**：稿子（`design/*/`）里轴名、单位、配色、
  标注、色标、门槛带常常是**逐项写死**的。用户实测四张图"根本不可读"，根因就是我按理解自造
  （轴用原始小数、热力图换了自己的配色、排行图丢了"邻域最差"、IC 图丢了门槛带）。
  **做法**：动手前把稿子逐项读一遍，做完**逐项点名核对**（轴名/单位/颜色/标注/图例/色标）。
- **11.5-117** 【★R4-b】**顶层弹层不吃父级 QSS；第三方控件的"想当然参数"要先验证**：
  ① `QCalendarWidget` 弹层是独立顶层窗口 ⇒ 必须给 `calendarWidget()` 单独挂样式
  （否则浅色主题下"年月"两栏白底白字、悬停才看得见）；② pyqtgraph 0.14 `ScatterPlotItem`
  **不认 per-point `tip`**（只认 `data`）⇒ 悬停要接 `sigHovered`。

- **11.5-118** 【★R4-c】**图表容器的三条硬规矩**：① **取景别用 min/max**（一个极端值就能把画面撑爆、
  其余点挤成一条）⇒ 用 **Tukey 1.5×IQR + 必含 0**，并把"视图外还有 N 个"写在图上；
  ② **图高要给上限**（只给下限会吃满余量、把下面的表顶出窗口）；③ **滚轮让给页面**
  （pyqtgraph/绘图库默认滚轮=缩放 ⇒ 在可滚区域里必须 `wheelEvent → ignore()`）。
- **11.5-120** 【★R4-d】**图表细节五条**：① "一堆格子"的判定**别用包围盒**（会把不相邻的格子
  一起圈住）⇒ 逐格描边 + 半透明，并把**判据写进图注**；② 压在数据上的字**给白底 + 夹边界**；
  ③ **色标读数方向跟渐变一致**（最深在顶 ⇒ 最大值写顶上）；④ 行高别压到下限（先算"能显示几行"
  再撑开行高，少显示要如实说明）；⑤ 格子窄了**刻度抽稀**。

- **11.5-121** 【★R4-e】**图例/解释与数据分家；空态别用 hide()**：① 图内只留短标签（≥11px + 白底），
  长句/口径走**图外说明行**（稿子是固定画幅 SVG，照搬到活控件上必然挡数据）；
  ② "这个视图现在没意义"要在**用户点开的那一页**里写清楚（`hide()` = 用户看到空白，
  提示躲在角落等于没说）；③ 图内字号别低于 11px。

- **11.5-132** 【★1.74 · "状态别从呈现反推" + "新键必须同步抹平冒烟"】**引导条"已读"从可见性反推 ⇒ 静默永不出现**。
  实测（用户 2026-10-15 复核）：`breadth_ui` 里存 `hint_done` 用的是
  `not self.hint_bar.isVisibleTo(self)` —— 而**页签没切到 / 窗口没显示时 `isVisibleTo` 恒 False**：
  · 切到别的子页签后保存 ⇒ `hint_done = True`（用户**从没关过**引导，却被标成已读）；
  · 切回 M3 再保存 ⇒ 又写成 `False` —— **同一个值随"什么时候保存"来回翻**。
  后果：引导条要么静默永不出现（用户看不到"这个阈值到底是什么"，正是他点名要的那条），
  要么莫名其妙又冒出来。**修法**：`p._hint_done` **显式标志**，唯一写点在"点知道了"
  （`on_hint_dismissed`），保存/恢复都读它；并加 2 条回归断言
  （① 换页签保存不许变已读 ② 关掉后从别的页签保存仍是已读）。
  【同轮暴露的第二条（更普遍）】**冒烟依赖用户真实偏好**：`breadth_ui` 只抹了 `col_order`，
  而我这轮给它加了 `items` / `hint_done` / `index_h` 三个**用户态**键 ⇒ 用户一用新功能，
  M3 段 **5 条断言立刻红**（行数 / 窗格名 / 引导可见性全被带偏）。
  **通用纪律**：**
  ① "用户做过什么"只能由**动作**记录 —— 绝不用"控件此刻可不可见/在不在屏幕上"推导**（离屏、
     非当前页签、窗口最小化都会让可见性恒假）；
  ② 给页面的"记住上次"**加任何一个新键**，同一次改动里必须把它加进 `smoke_pages_overlay`
     开头的**抹平列表**（§11.5-70/90 同族）—— 否则"用户用得越久，冒烟越红"，
     而红的原因看起来跟这次改动毫无关系；③ 阈值类偏好（如 `sweep3dense`）在**接通 UI 的那一轮**
     也要一并加进抹平列表。

- **11.5-133** 【★1.75 · "记号要跟着载体走" + "数值控件的类型"】**同一段文案在两种载体上不能混用记号**。
  实测（期 2 写闸条时）：`GateHintBar` 的文案里有 `<br>`/`<b>` ⇒ Qt 把它当 **rich text** 渲染
  ⇒ 同一段里我顺手写的 `**不适用**` **原样显示了两个星号**（用户会看到"星号"）；
  而 `setToolTip(...)` 是**纯文本**、`**` 在 tooltip 里是**全仓既有风格**（`ui/settings_registry.py`
  实测 **69 处**、既有项也这么写 —— 我一开始想去"顺手修"，查完发现那是约定、不是毛病）。
  **纪律**：① **先认载体，再选记号** —— rich text 用 `<b>`/`<br>`，纯文本才用 `**`；
  ② 给一段文案**加了任何一个 HTML 标签**（哪怕只是 `<br>`），同一段里的 `**` 必须**一起**改成 `<b>`
  （否则一半渲染、一半露星号）；③ 想"顺手统一全仓记号"之前**先量**（69 处是老约定，改了才是破坏一致）。
  【同族 · 数值控件的类型（同一轮踩两次）】
  · `QSpinBox.setRange(5.0, 99.0)` / `.setValue(30.0)` ⇒ **`TypeError`**（int 档只吃 int）；
    修法是**按控件类型放值**（`isinstance(sp, QDoubleSpinBox)` 分流），别指望 Qt 替你转；
  · 放在**可滚动容器**里的 SpinBox **必须用 `NoWheelSpinBox`/`NoWheelDoubleSpinBox`** ——
    普通 SpinBox 会在用户滚动抽屉时**悄悄改值**（那两个包装类就是为它存在的，§10-9 同族）；
  · 断言里出现 `get_scan_store().entries()` 这类"名字像集合、其实是**计数/摘要**"的返回值时，
    别直接 `len()`（本轮实测 `TypeError: object of type 'int' has no len()`）—— **先看清类型再写断言**。

- **11.5-127** 【★1.70 · 窄容器排版】**"并排"是窄抽屉的头号杀手；`QStackedWidget` 的最小宽 = 所有页最大**
  —— 用户实测（2026-10-11）：M1 配置抽屉里"内容全挤在一处、**后面的完全看不到**，**拉长窗口也不显示**"。
  逐个量出来的根因（全部可复现）：
  · `买卖条件` / `大盘门控` 两卡把「买入 + 卖出」**并排**放 ⇒ 每侧只剩半幅（~250），
    而一组条件行（变量 + 规则 + 数值 + ✕）最小 ~400 ⇒ 右侧那组被压到 ~130、**内容直接截断**
    （卡片最小宽实测 **846 > 抽屉 525**）；
  · `风控` 四项挤一行（最小 **666**）⇒ 最右「移动止盈回撤」整组不见；
  · `成交模型` 主选项 + "多等多少钱"挤一行（最小 **532**）⇒ 把 `QStackedWidget` 顶到 **558**
    ⇒ **五张卡全部**多出一条 33px 横向滚动条（它取**所有页里最宽的那页**，与当前显示哪页无关）；
  · 抽屉宽度公式 `min(560, 页宽×0.42)` **在 560 封顶** ⇒ "拉宽窗口"对手宽卡片毫无帮助（用户困惑点）。
