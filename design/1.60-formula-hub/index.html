ƒ 函数总库（Formula Hub）· 样式设计稿 当前 v1

目标：给散落在三处的用户函数一个统一保管与管理的地方 —— 增删查改、编写、语法体检、互送到各功能页；图表叠加 / 回测运行 / 全市场扫描仍在功能页完成。 同时为 B15 参数稳健性研究铺路（B15 的"策略选择"直接从总库取函数，不用再各处抽文本）。

四版方案：A 双栏管理台（主推） · B 全局浮窗 · C 右侧抽屉 · D 表格密集台（A 的高级视图，同一份数据）

二、统一数据模型提案（选型时一并拍板；实现细节在方案书定稿）

segments + params 被引用 → 行情页配方
+ 窗格目标 M1 策略

+ 粗筛阈值/范围 B15 参数研究
+ 网格/区间
选项做法收益代价
① 真源统一
（资产 / 引用分离）		 新函数资产库为唯一公式真源；M1 策略 / M2M3 方案存引用 + 内联快照 （快照保离线可用，引用保同步与 B15 抽取）；首版做一次性幂等迁移（三处现有函数抽成资产，原文件保留兜底） 真打通：改名/改函数一处生效；删除有引用检查；B15 直接取资产 动三个存储的写入语义，迁移要谨慎（工作量最大）
② 统一视图
（分存储聚合）		 总库只做聚合管理面：读三个 store 汇总展示，写入仍走各自 store 改动最小、风险低；管理体验先拿到 同一函数多副本的漂移依旧；B15 还得再做一次抽取
本轮倾向：①（用户的原话"把整个函数层面打通"）——但迁移规模在方案书里 逐条列出后再开工；设计稿四版对两个选项都成立（UI 不变，换的是数据层）。

三、四版交互模型对比（点标题可打开交互原型）

方案入口 / 位置编辑器优点代价适合
A 双栏管理台
主推		 左轨新增「ƒ 函数库」页（建议落位：回测与数据管理之间，待拍板） 右栏常驻（查看 ⇄ 编辑零跳转） 函数有了"中立的家"；空间充足；全库体检 / 引用管理放得下 左轨多一个导航位（设置页"永不上移"口径不受影响） 函数会持续变多的主线形态
B 全局浮窗 三个功能页各一个「ƒ 库」按钮，非模态浮窗（位置记忆） 紧凑单列三态 零导航侵入；边看图边翻；范本现成（下载队列面板） 编辑长函数偏挤；浮窗生命周期要照 §11.5-81/82 管 不想动导航 / 轻量管理
C 右侧抽屉 任意功能页滑出（复用 EditDrawer 组件） 页签三态（列表/详情/编辑） 组件现成、实现最省；结果区一像素不动（§10-14） 没有中立的家；可发现性靠三页入口 最快落地
D 表格密集台 同 A 的导航位，切换"卡片 / 表格"两种视图 表格只做总览与批量动作，编辑跳 A 函数上量后的体检 / 批量清理最好用（KPI 行 + 过滤器） 不适合当唯一视图（编辑体验弱） 作为 A 的进阶视图共存（S4 之于 S2 的关系）
推荐组合：A（主视图）+ D（上量后的高级视图，同一份数据）； 若不想动导航则 B。选型后按惯例出施工路径表（每步一验收）。

四、设计语言与功能边界

· 观感 = 现行主程序：白卡 / #E6EAF0 边 / #1976D2 主蓝 / 圆角 14 / 字号 13；代码区用开源等宽栈（§10-15，连 font: 简写也不写专有名）。
· 语法体检 = 调 FormulaEngine.validate / parse：错误给人话 + 位置；已知未实现的绘图函数 = 非阻断提示（§11.5-14）；绝不阻断载入存量函数。
· 删除分级 = §10-10：未引用 → 红色二次确认；被引用 → 键入「删除」+ 引用清单列出。
· 互送语义 = 复用既有「送去做回测」：载入（回填段与参数）+ touch used_at；运行永远在功能页。
· 隐私 = §10-6：本目录样例全部为公开教科书级公式（MACD / 均线 / 乖离率），不含任何用户私有函数。

五、待拍板决策点（选型时回答）

① 样式：A / B / C / D（或 A+D 组合）；
② 若 A/D：左轨落位（建议 = 📐市场回测 与 🗄数据管理 之间）；
③ 数据模型：提案①（真源统一 + 引用，推荐）还是提案②（聚合视图）；
④ M1 的 function 拼接文本、M2/M3 的 formula 内联文本 —— 迁移时是否顺便统一成段结构（影响 B15 的参数发现精度）。
