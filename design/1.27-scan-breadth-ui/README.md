## 0. 定位与边界（先说"不做什么"）

| 项 | 结论 |
|---|---|
| M2 | **某一天**的全市场横截面：哪些股票当天满足"函数段 + 条件 Gate" |
| M3 | **逐日**广度：每天有多少只满足条件（家数 / 占比），可叠加指数 |
| 关系 | **同一个内核，两种视图**（M2 = 纵向取一列；M3 = 横向按日求和）。**不做两个引擎** |
| 数据范围 | **只做量价 + 自研公式**（技术面）。`valuation` / `fin_report` 无数据源 ⇒ **本轮不做** |
| 联网 | 扫描页**只读数据湖**，不联网；一切下载走 `MarketSyncService`（§9-H 红线） |
| 与 M1 的关系 | 复用同一套「函数段 + 条件 Gate」编辑器与公式引擎；**不并入** `SingleStockBacktestView` |
| 与 §6.5 远期 | 组合级多标的引擎（择时后挑股 + 资金分配）**是另一件事**，不并入本轮 |

## 1. 最大效率的三条杠杆（结论：不做"逐只读文件直接算"）

### 杠杆 1 —— 干掉 IO：建**扫描专用面板** `kline_panel`
现状数据湖是**按标的存 parquet**，看一只很快、看一列最慢（5000+ 次文件打开）。
⇒ 派生一层 **日期 × 标的 的宽表**（按日期分区，float32，只放 OHLCV）：

- **一次建、多轮复用**（M2 / M3 / 改配方都吃它）；
- 对齐用 NaN ⇒ **天然承载"数据不足"三态**（新上市 / 退市 / 停牌各就各位）；
- **增量追加**新交易日，不需要每次重建；
- 是**派生数据**（可从 `kline_daily` 重建）⇒ 无数据主权风险。

### 杠杆 2 —— 干掉"逐只 Python"：沿标的轴向量化
面板是二维数组后，MA/MACD 这类指标沿时间轴滚动、**一次算完全部标的**。
M2 只取尾部窗口、M3 取整段。需实测确认与原 pandas 口径逐位一致（探针 P3）。

### 杠杆 3 —— 两段式漏斗（最容易被低估）
先用在面板上**极便宜的粗筛**把候选从 5000+ 砍到几百，再对候选跑完整公式：

> 成交额 > X · 量 > 0（非停牌）· 非 ST/退市 · 上市 > N 日 · 涨跌幅在合理区间

真实策略命中率通常 < 5%，漏斗能让精算量降一个数量级。

## 2. 缓存与失效（`scan_cache` 的正确姿势）

| 层 | 内容 | 收益 |
|---|---|---|
| **L1 面板缓存**（主力） | `kline_panel` 本身 | 改配方 / 换日期都不用重读 IO —— **通用收益最大** |
| **L2 结果缓存**（按需，本轮可后置） | `公式指纹 + 复权 + 样本口径 + 日期范围 + 数据版本` → per-symbol 布尔 | 只对"同公式反复切日期"才值得 |

**★ 失效必须含"数据版本"**（分区 mtime / `get_latest_date` / 行数指纹），**不能只看公式哈希**
—— 否则"新下载了数据但不重算" = **静默陈旧**，违反 §5/§10 铁律。

---

## 3. M3 的天然增量

`breadth[date]` **只依赖 ≤ date 的数据** ⇒ **新交易日只算最后一天**，历史一天都不重算。
唯一例外：数据被修订 / 复权口径变化 ⇒ 提供「全量重算」（危险动作隔离 + 二次确认）。

## 4. 与「🗄 数据管理」的联动（互利共赢 · 6 条规范）

> 核心思想：**"扫描需要什么"变成数据管理的一个预设；"数据管理的下载/体检"变成扫描的一行回执。**

1. **就绪度体检（双向唯一口径）**：扫描页开跑前体检 `已就绪 N/总 M`、缺口清单、区间是否够
   （含公式最小历史长度）、数据健康（复用 §9-V 非正价 / 量纲接缝判据）+ **「补齐缺失（增量）」**
   按钮（后台就是现成的 `SyncWorker`）。
2. **反向**：`bulk_download` 新增**「全市场扫描就绪」预设**（全A + 起点 + 复权），一键备齐底座。
3. **面板作为可见分区**：`ZONE_ORDER` / `ZONE_LABELS` 新增一项，显示 行数/日期范围/体积/更新时间，
   支持删除 + **「从日线重建」**（危险动作隔离 + 键入确认，与"清空分区"同款闸门）。
4. **增量语义共用**：两页同用 `fresh_within_days=0`（末日==今天才算最新）、"空增量 = 已最新不是失败"。
   **否则会出现"管理页说最新、扫描页说缺数据"** 这种让用户失去信任的矛盾。
5. **下载顺序由"扫描损失"驱动**：缺口清单带优先级（按成交额/流通市值降序）⇒ 广度先接近真实。
6. **问题清单回流**：读不出 / 校验不过的标的回写数据管理的问题清单 + 「重新全量下载该只」入口，
   **不在扫描页静默跳过**（§9-V 护栏的自然延伸）。

## 5. 复权口径（折中方案）

- 难点：前复权**指标更合理**（除权日无假跳空），但会**随除权重写历史** ⇒ 面板/缓存失效。
- 折中：**面板存"不复权 + 复权因子"**（因子 = `kline_daily` ÷ `kline_daily_raw`，两分区都已有），
  指标计算时**按需向量化复权** ⇒ 面板稳定 + 指标正确。
- 单日横截面两个口径**当日值相同**（前复权只改除权日之前）⇒ M2 基本不受影响，受益主要是 M3 长周期指标。
- 简化选项：**MVP 只用不复权**，界面明示"本次扫描口径 = 不复权"，因子后置。

## 6. 设计规范（Design Spec）

### 6.1 版式分层（§10-14 落地）
| 层 | 内容 | 常驻 |
|---|---|---|
| **页签** | 单股回测 / 全市场筛选 / 广度统计（现有 `backtest_module` 壳，仅换占位页） | ✅ |
| **L1 操作轴** | 样本范围 · 日期/区间 · 复权 —— **1 行** | ✅ |
| **L2 摘要条** | 配置 chips（ƒ函数 / ⇄条件 / 🎚粗筛 / 🌐样本 / 📅日期）+ **数据就绪回执** + 主按钮 | ✅ |
| **L0 结果区** | M2 = KPI + 结果表；M3 = 双窗格折线 —— **吃满剩余高度** | ✅ |
| **L3 配置抽屉** | 函数段 / 条件 Gate / 样本口径 / 粗筛 —— **覆盖层，不动主区高度**（§11.5-26） | ❌ 点击才出 |

### 6.2 色彩与形态（沿用现状配色，深色主题仍推迟）
`accent #1976D2` · 涨 `#2E7D32` · 跌 `#C62828` · 警示 `#E65100` · 页面底 `#F4F6FA` ·
卡片 `#FFF` + `#E4E9F0` 边 + radius `8/14` · 字号 `12.5–13.5` · 表行高 `28`

### 6.3 ★ 三态语义（本项目最容易骗人的地方）
| 态 | 含义 | 视觉 | 纪律 |
|---|---|---|---|
| 命中 | 满足条件 | accent 实心 pill | — |
| 未命中 | 明确不满足 | 灰 pill | — |
| **数据不足** | **既非命中亦非未命中**（历史不够 / 停牌 / 上市不足 N 日） | **橙 pill + 计数显式** | **绝不用 0 / False 冒充**，广度分母必须同时显示"有效样本数" |

### 6.4 口径必须"印在标题上"
M3 标题示例：`📊 广度（全A · 剔除ST · 上市>250日 · 有效 4821/5390 · 不复权）`
—— 否则"家数"没有可解释性。

### 6.5 术语人话化（§10-10）
"横截面" → **"某一天的全市场筛选"**；"广度" → **"每天有多少只满足条件"**；
"样本口径" → **"统计范围"**；"scan_cache" → **"扫描缓存"**。

### 6.6 危险动作与回执
- 「全量重算」「删除面板」= 隔离位置 + 二次确认（§10-10）；
- 进度/结果回执**一行化**，详解进 tooltip（§7-B6 STEP 5 同款）；
- 空态 / 未就绪 / 失败三种文案，**每种都给下一步动作**，禁止静默。
