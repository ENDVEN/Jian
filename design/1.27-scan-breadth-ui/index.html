  • ① 湖的形态是为"看一只"优化的（行情工作台），对"看一列"最差 —— IO 会成为主要成本，而不是计算。
  • ② 逐只 pandas 求值：5400 次 Series 构造 + 循环，比向量化慢一个数量级。
  • ③ 最容易骗人的地方是"数据不足"：某股只有 120 根但函数要 MA250 —— 它既不是命中也不是未命中。 若按 False 计入，广度会系统性偏低、横截面会漏股。
  • ④ 缓存失效若只看公式哈希：新下载的数据不会触发重算 ⇒ 静默陈旧（违反 §5 / §10 铁律）。

二、主轴：一个引擎，两种视图（＋三条效率杠杆）

M2 和 M3 是同一个计算的两面：对每只股票，把「函数段 + 条件 Gate」在它自己的日线序列上跑一遍， 得到逐日布尔信号 ⇒ M2 = 某一天纵向取一列（命中清单），M3 = 跨标的按日横向求和（家数）。 ⇒ 不做两个引擎，缓存也只有一份。
杠杆做法为什么有效
1 · 干掉 IO 派生 kline_panel（日期 × 标的 宽表，按日期分区，float32，只放 OHLCV），一次建、多轮复用，增量追加 把 5000+ 次小文件读，变成一次列式扫描；NaN 对齐天然承载"数据不足"三态；派生数据可从日线重建
2 · 干掉逐只 Python 面板是二维数组后，指标沿时间轴滚动、一次算完全部标的 去掉 pandas 构造开销，计算量从"5400 次"变成"一次"（需探针验证口径一致）
3 · 两段式漏斗 先用便宜列粗筛（成交额 / 非停牌 / 剔 ST / 上市 > N 日）砍到几百，再跑完整公式 真实策略命中率通常 < 5% ⇒ 精算量降一个数量级

4.4 其它硬规范

  • 口径必须印在标题上：📊 广度（全 A · 剔除 ST · 上市 > 250 日 · 有效 4821/5390 · 不复权） —— 否则"家数"没有可解释性。
  • 术语人话化（§10-10）："横截面"→"某一天的全市场筛选"；"广度"→"每天有多少只满足条件"；"样本口径"→"统计范围"。
  • 回执一行化：进度/结果写成一行（扫描 2317/5390 · 命中 96 · 失败 2 · 用时 1.8s），详解进 tooltip（§7-B6 STEP 5 同款）。
  • 危险动作隔离：「⟳ 全量重算」「删除面板」= 放底部/抽屉底 + 二次确认（§10-10）。
  • 三种空态都要给下一步动作：未就绪 → 「补齐缺失」；无数据 → 「去数据管理」；失败 → 「重试 / 查看原因」。禁止静默。
  • 双击结果行 → 行情工作台（复用 load_symbol），不另做看图器。

六、与「🗄 数据管理」的联动（互利共赢 · 6 条）

核心思想："扫描需要什么"变成数据管理的一个预设；"数据管理的下载 / 体检"变成扫描的一行回执。 两边只有一份实现（下载一律走 MarketSyncService）。
  • ① 就绪度体检（双向唯一口径）：开跑前算 已就绪 N/总 M、缺口清单、区间是否够 （含公式最小历史长度）、数据健康（复用 §9-V 非正价 / 量纲接缝判据）+ 「补齐缺失（增量）」按钮。
  • ② 反向：bulk_download 新增 「全市场扫描就绪」预设（全 A + 起点 + 复权），一键备齐底座。
  • ③ 面板作为可见分区：ZONE_ORDER / ZONE_LABELS 新增一项，显示 行数/日期范围/体积/更新时间， 支持删除 + 「从日线重建」（隔离 + 键入确认，与"清空分区"同款闸门）。
  • ④ 增量语义共用：两页同用 fresh_within_days = 0（末日 == 今天才算最新）、 "空增量 = 已最新不是失败" ⇒ 杜绝"管理页说最新、扫描页说缺数据"。
  • ⑤ 下载顺序由"扫描损失"驱动：缺口清单带优先级（按成交额降序）⇒ 广度先接近真实。
  • ⑥ 问题清单回流：读不出 / 校验不过的标的回写数据管理的问题清单 + 「重新全量下载该只」入口， 不在扫描页静默跳过。
