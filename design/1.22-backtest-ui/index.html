三、四个样板的取舍对照

样板交互模型看得见的好处代价 / 风险适合
A 摘要条配置 → 一行 chips（可点开） 一次性解决"配置挤结果"；还顺带解决了"我到底配了什么"看不见的问题（chips 本身就是状态摘要） 编辑时若用遮罩抽屉会盖住结果（可改为就地展开规避）绝大多数日常使用
B 左栏工作台图标栏 ↔ 展开面板 改参数与看结果同屏，调参迭代最快；栏位可钉住 展开时挤压图表宽度；图标栏的图标语义要靠记忆（需要 tooltip 兜底）高频调参的重度用户
C 步骤流4 步各自独占屏 每一步空间最充裕，教学/首次配置体验最好；结果页最干净 来回切步才能边改边看，反复微调时最烦首次配置 / 配置改动很少的用户
D 可停靠面板面板可停靠/浮动 + 预设 自由度最高，用户自己决定比例；三套预设覆盖所有场景 Qt 里工程量与坑最多（停靠/浮动状态、pyqtgraph 尺寸联动）；样式的统一性最难守专业版/进阶用户

五、我的推荐：A 的骨架 + D 的"可拖分栏"（混合方案）

  • 常态 = 样板 A：一行摘要条 + KPI + 结果区吃满（结果区 ≈ 75%）。
  • 点 chips / ⚙ = 在结果区上方就地展开该编辑卡片（一次只展开一个，默认占 ~35% 高，可拖分隔条）—— 避开"遮罩抽屉盖住结果"的缺点，实际拿到样板 D「调参数」预设的好处。
  • ⊕ 保留一个 📌"钉住编辑区"（借样板 B）：钉住后改完直接 ▶，不用反复开合。
  • 默认进入看结果；把"上次的展开状态"写进 preferences.json（沿既有单例，不新增存储）。
顺路收益（很重要）：这次 UI 结构改造天然把 1697 行的 ui/views/backtest.py 切成 4~5 个子构件 （摘要条 / 编辑卡片×3 / 结果区），正好一次性完成 §9-L 大文件拆分 —— 否则先改 UI 再拆文件 = 同一块代码改两遍（我上一条消息提过这个风险）。

七、需要你拍板的 4 点

  1. 交互模型选哪个？ 直接选 A / B / C / D，或者说"用你推荐的 A+D 混合"。
  2. 打开页面时默认长什么样？ 「看结果」（配置全收，结果最大）还是「调参数」（配置常驻一半）？ （我建议默认看结果 + 记住上次状态）
  3. 允许"配置区完全不可见"吗？ 即用户可以不展开任何编辑区就完成回测（用上次配置直接 ▶）。 若不允许，就保留一列常驻摘要 = 样板 B/D 的形态。
  4. 顺路做 §9-L 拆分吗？ 我建议做（一次规划，改一遍）。
