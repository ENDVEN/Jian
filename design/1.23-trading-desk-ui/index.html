1.23 行情工作台 UI 收口 · 四套设计语言样板

需求（你的原话）："流程一样" —— 先出几版样板图、用不同的设计语言，你挑一个再动手。 下面是 4 套可交互样板，设计语言彼此不同（不是换皮），都能满足 §10-14 的版式分层； 另外本轮的 分钟周期（§7 D3） 会共用同一条图形工具条 —— 所以我在 4 套样板里都预留了"周期第 4 档"的位置。

一、先把"现状为什么难受"量化（用代码实测，不用感觉）

左栏常驻宽度
240 ~ 300 px
左栏内容高度需求（实测）
≈ 900 px
左栏实际可视高度（900p 屏）
≈ 600 px
同类优先级的常驻分组
6 组
  • ① 图表高度其实够（左栏是纵向的，图表占满整高）—— 本页的病不是"抢回高度"，而是三件别的事， 这一点与回测页不同，我在下面写清楚，避免照搬回测页方案。
  • ② 左栏要滚动才发现功能：自选股 setFixedHeight(150) + 周期 + 复权 + 主图叠加 + 公式（4 个按钮 + 状态） + 附图 + 标注工具（下拉 + 3 个按钮 + 状态）→ 后半夜才用到的「🛠 标注工具」默认在视野之外。
  • ③ 6 个分组视觉权重完全相同（都是「小标题 + 控件」平铺）—— 用户无法一眼判断"哪个是我的高频操作"。
  • ④ 状态回执被窄栏压窄：复权回执 / 公式回执 / 标注回执都是 11px 的 QLabel 挤在 240px 里， 内容靠 tooltip 兜底 —— "我到底配了什么"看不见。
  • ⑤ 图表让渡了 20% 宽度给常驻左栏，而左栏里一半控件是"配一次就不动"的。
顺带纠正文档一处失真（本次要清的账）：§9-U 把本页病灶写成"图表被压成下半屏"—— 实测并不成立（图表占满整高）。真实病灶是上面的 ②③④⑤。这属于本轮 A 项"清文档账" 的一部分，收工时一并修正。

三、四套样板的取舍对照

样板配置去哪了看得见的好处代价 / 风险适合
A 深色终端 52px 图标轨 + 320px 面板（点图标展开/再点收起） 一屏信息密度最高；周期/复权用分段控件，少一次点击；底部常驻十字光标读数（看盘人最在意这排数字） 深色与其余 5 页（浅色）割裂，等于全 app 要两套色板；等宽字体与密集排布对非专业用户偏硬 你本人天天看盘 · 已习惯终端风格
B 左栏工作台 左栏分组卡片（每张可折叠，默认展开自选股） 与 1.22 回测页完全同一语言（白卡/圆角/蓝），学习成本为 0；左栏宽度可收（44px）；自选股可点即切 图标轨方案相比"折叠卡片"少了宽度节省（卡片折叠只是变矮，不省宽）；左栏仍占 300px 最稳的选择（我默认推荐）
C 沉浸 HUD 右侧玻璃抽屉（4 页签）+ 底部胶囊 + 左侧工具轨 图表真正 100% 铺满，宽度全拿回来；静置自动淡出让"看图不被打扰"；钉住后与常驻等效 "东西藏在浮层里"需要用户适应；淡出/浮层与 Qt 的 QGraphicsView 尺寸联动是最容易出坑的一处；正文小字在玻璃上有对比度风险（需走对比度守卫思路） 想要最大图表面积 · 愿意接受新鲜交互
D 纸感极简 文本式摘要 + 图表上方浮出的"纸片编辑条"（不挤高度） 层次全靠排版，长时间盯盘最不累眼；摘要本身就是"我配了什么"的答案（与回测页 chips 同一思想，但更轻） 可点击的"文字短语"发现性弱（新用户不知道能点）；衬线体在 Windows 上中文字形依赖系统字体，跨机表现不完全可控 看重护眼与克制感

四、无论选哪个，这四条都是施工硬约束

约束为什么对样板的要求
① 常驻 ≤3 行§10-14 版式分层（L0 主角 / L1 操作轴 / L2 摘要 / L3 编辑 / L4 附属） 4 套样板都已满足：A=2 行、B=2 行（顶栏 + 工具条）、C=0 行（浮层）、D=1 行（摘要）
② 低频配置必须离开常驻自选股管理 / 公式编辑 / 标注工具 / 数据同步 = 配一次用很久 4 套都有明确的"低频落点"（面板 / 折叠卡 / 抽屉 / 纸片条）
③ 状态摘要必须常显"我到底配了什么"看不见 = 现在最痛的点（回执挤在 240px 里） A 用工具条 chips、B 用卡片内回执 + 图上指示、C 用胶囊、D 用文本摘要
④ 周期控件要能扩到第 4 档（分钟）本轮同时要做 §7 D3 分钟周期：kline_min 分区已预留，日期格式只需改 adaptive_axis.choose_date_format 一处 4 套的周期控件都是"分段 / 胶囊"，加一档不用重排版；若你选 B，我会把分段控件做成可容纳 4~5 档

五、我的推荐

  • 推荐 B 为主骨架：它是 1.22 已验收的同一套语言，迁移成本最低、回归风险最小（两个冒烟脚本里页面级断言最多的就是本页）， 并且天然解决现状的 ②③④⑤ 四点病灶。
  • 吸收 A 的两个零件（与设计语言无关、纯交互改进）：① 周期/复权改分段控件（少一次点击）； ② 图表区常驻十字光标读数条（现在读数只在图上飘一个 tag，静置就没了）。
  • 吸收 C 的一个零件：左栏做个"收起"按钮（300px ↔ 44px 图标条），需要大图时一键让位 —— 比 A 的常驻图标轨更保守。
  • 吸收 D 的一个零件：把"公式状态 / 复权回执 / 标注回执"从 11px 小灰字升级为可读的一行摘要（不是靠 tooltip 兜底）。
  • 不建议选 A：深色终端会让本页成为全 app 唯一的深色页，长期维护两套色板不划算。 若你确实喜欢深色，我建议单独开一轮"全 app 深色主题"，而不是只改这一页。
顺路收益（与上一轮同理）：本页 ui/views/trading_desk.py 847 行 已在 §9-U / §9-L 名单上。 这次 UI 收口天然把它切成"图形工具条 / 左栏面板 / 图表装配"三块 → 一次规划、改一遍， 不必"先改 UI 再拆文件"。

六、落到 PyQt6 的实现成本（诚实评估）

样板新增 / 改造关键坑回归影响
A图标轨 QFrame + 面板 QStackedWidget + 底部读数条 深色主题需要新色板与 custom_widgets 的 QSS 常量扩一套（§10-9 要求样式唯一来源） 中（样式相关断言最多）
B左栏分组卡片（可复用 backtest_panes 的卡片构件思想）+ 工具条分段控件 折叠卡要"记住折叠状态"（写 preferences，与 1.22 的 backtest_ui 同源做法） 低~中

七、需要你拍板的 5 点

  1. 选哪一套？ 直接说 A / B / C / D，或"用你推荐的 B + A 的两个零件 + C 的收起按钮"。
  2. 左栏要不要能"收起"？ 收起后图表多拿 ~260px 宽度（推荐要）。
  3. 公式状态 / 复权回执 / 标注回执 是要"一行可读摘要"（推荐）还是维持小灰字 + tooltip？
  4. 分钟周期（§7 D3）这一轮一起做吗？ 一起做的话，周期控件我按 4 档（日/周/月/分钟）一次排好，避免二次改版。
  5. 顺路拆 trading_desk.py（847 行）吗？ 我建议做（与上一轮 backtest.py 同一套做法）。
