## 背景（用户原话）

> "现阶段我们的 M3 主要针对单一方案做全市场的数量统计，我想能不能支持**同时统计多个方案**、
> 叠加在同一张图上显示，或者变成**多行显示**，或者直接**叠加在 K 线图上**…… 就像市场情绪一个是
> 80 以上一个是 20 以下，我想看看这两个极端数据到底跟上证指数有什么关系，在 80 和 20 之间又是什么样的情况。"

## 建议落地顺序（每期独立可交付）

| 期 | 内容 | 成本（相对现状） |
|---|---|---|
| 期 1 | 多统计项：**同一段公式的多个判定变量一次扫描**（共享读盘/准备帧）+ A/B 表现切换 | 低：第 2 项起只需多算一次公式（读盘共享；重复扫命中会话缓存） |
| 期 2 | 事件对齐图（含样本数 / ±1σ / "独立事件"口径） | 中：纯计算、可缓存 |
| 期 3 | 关系量化卡（IC / 领先滞后 / 置换检验）+ K 线色带 | 中：IC 口径复用参数研究，不另写一套 |
| 期 4 | 多方案（不同公式/参数/范围）各自缓存 + 统计项面板 | 中高：N 次扫描，靠会话缓存兜住 |

## 三个必须先定的口径问题（否则做到一半会返工）

1. **事件的独立性**：连续命中（一段行情连续几十天命中）会让 n 虚高 ⇒ 必须同时给"命中间隔 ≥ 5 日的
   独立事件"口径（D 页稿里已列出两套 n）。
2. **占比的分母**：`命中 / 有效样本` 与 `命中 / 全样本` 是两回事，图上必须写清（现状口径 = 命中/有效）。
3. **多方案比较的多重检验**：比 5 个方案 × 3 个窗口 = 15 次检验，随便挑最好的那个当结论就是 p-hacking
   ⇒ 置换检验 + 显式提醒（这是"软件替用户把关"的价值点，也是 §10-4 诚实性的一部分）。
