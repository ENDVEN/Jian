⚙ 设置页 · 四版样式（请挑一版，或指出混搭）

四版的功能清单完全一致（账号与数据源 / 下载与取数 / 外观与个性化 / 回测与扫描默认 / 存储与维护 / 关于）， 差别只在信息组织方式与观感。位置按你的要求：左导航最下方固定。

S1 · 分组卡片 + 左锚点

贴近现有「数据管理 / 运行历史」的语言
  • 优点：学习成本最低，与现有页面最像；锚点跳转快
  • 优点：分组卡片天然适合再加分组
  • 代价：项多时（>40）纵向会变长，需靠锚点/搜索
打开 S1

S2 · 系统设置双栏

macOS / iOS「系统设置」观感，宽松
  • 优点：一屏只看一组，焦点强、最不容易误改
  • 优点：留白大、观感高级；适合面向新用户
  • 代价：同屏信息量最少，参数多时切换频繁
打开 S2

S3 · 控制台单页 + 搜索

顶部搜索 + 右侧「当前状态 / 网络自检」
  • 优点：搜索直达；右侧常驻状态（登录档位/出口/额度）最实用
  • 优点：适合"改完立刻看效果"的设置（主题、密度）
  • 代价：右侧栏占宽；窄屏要折叠
打开 S3

S4 · 密集参数表

每行：当前值 / 默认 / 作用域 / 来源文件
  • 优点：参数爆炸后的正解——可过滤、可排序、可一键回默认
  • 优点：「来源」列直接显示落在哪个偏好键/文件，排障最快
  • 代价：观感偏工程化；对纯"外观个性化"不够直观
打开 S4
我的建议（供你参考）：S3 + S1 混搭最稳 —— 外层用 S1/S3 的分组卡片保证"看得懂、像现有软件"，再把最上面一条做成 搜索框 + 右侧状态卡（S3）；等你哪天参数过百，切到 S4 的表格视图做"高级模式"即可（两视图共用同一份注册表）。

技术前提（决定了后续扩展成本）：无论选哪版，实现都走同一套 ui/settings_registry.py 声明式注册表（每项声明 key/类型/默认/校验/作用域/落点/是否需重启）， 页面只负责渲染 ⇒ 以后加设置 = 加一行声明，不用改页面、也不会各页各写一套。
