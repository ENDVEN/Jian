## 二、逐条归纳（R1 – R12）

### R1 · 自选股必须带「分组标签」  ｜性质 ② 软件功能（可先做）

- **原话要点**：自选股里一定要添加现在的分组标签；分组一方面是给用户做**股票分类**，
  另一方面是方便今后想做**组合配置**时，直接对整个组合回测，进而调整里面的股票构成。
- **设计**：`★ 自选股` 页顶部一排分组 chips（`全部 / 核心白马 / 科技成长 / 高股息 / ＋新建分组`）。
  点标签切换该组清单；同一只股票**只能属于一个分组**（分类语义），"全部"是聚合视图。
- **落点**：扩展 `data/watchlist_store.py`（新增 `group` 字段 + 分组 CRUD + 坏数据容忍）。
- **注意（§5 铁律）**：分组只影响归类，**绝不允许**"删除分组连带删除自选股"；
  删组 = 解绑归到默认分组，且有二次确认。

### R2 · 两条添加入口  ｜性质 ① UI + ② 功能（小）

- **原话要点**：用户可以选择**从自选股里添加股票**，或者**输入代码或股票名称快速添加**。
- **设计**：
  - 路径 A「输入代码/名称」→ 带自动补全的输入框 + 目标分组下拉 + 回车即加入（复用既有 `search_symbol` 模糊检索）。
  - 路径 B「从自选股里挑选…」→ 勾选已有自选，批量移入某分组。
- **⭐ 位置（用户二轮反馈定死）**：「添加股票」这一块**必须摆在「分组」之上** ——
  理由原话："因为这是最主要的功能"。⇒ 本页自上而下 = `添加股票` → `分组标签` → `成分清单`
  → `组合配置预留位` → `分组管理（危险，默认收起）`。
- **依赖**：R1（没有分组就没有"移入目标"）。

### R3 · 分组标签右侧显示「组合当日整体涨跌」  ｜性质 ② 功能（中）

- **原话要点**：标签右边显示最近一天整个分组里整体股票涨跌情况，
  就类似于整个股票就是一个基金组合 —— **这个组合今天涨跌了多少**。
- **设计**：`核心白马 +0.82%`（绿涨红跌，与 App 全局口径一致）。
- **⭐ 用大白话讲清"口径"到底是什么**（用户 2026-09-17 说"没搞懂这个问题是什么"，故写死在这里）：
  > **问题一：多个涨跌幅，怎么合成一个数？**
  > 你的「核心白马」里有 4 只，今天它们各涨跌 +1.23%、+0.42%、+0.31%、−0.64%。
  > 最简单就是**直接平均** = (1.23+0.42+0.31−0.64) ÷ 4 = **+0.33%** —— 这叫**等权**
  > （把每只股票当成买了同样多的钱）。
  > 但真实账户不是这样的：你买 A 股 10 万、B 股 1 万，A 涨 1% 赚 1000、B 涨 1% 只赚 100
  > —— **钱的比重要紧**。按钱算出来的就是**按权重算**。
  > ⇒ **现在的处理**：还没有"权重"这个数据（组合配置是后面才做的），所以**先按等权（直接平均）**；
  > 等你在「组合配置」里设了每只的占比，**自动改成按占比算**。
  >
  > **问题二：某只股票今天没有数据怎么办？**（停牌 / 本地还没下载 / 已退市）
  > 三种做法，(a) 当成 0%（不涨不跌）会把整体数字**冲淡** = 骗人；
  > (b) 把它**排除**、只平均有数据的；(c) 干脆不显示。
  > ⇒ **现在的处理 = (b)**：**不算它**，并在标签上打一个 `⚠`，
  > 鼠标移上去告诉你"是哪一只、为什么没算"（§10-4 诚实原则：宁缺勿假）。
- **性能风险（真实）**：N 只股票要读 N 份日线 ⇒ 与 §9-O10「复盘页无 Parquet 缓存」同类。
  建议**按 symbol 做 LRU**（只取最近两根的 date/close 两列），并在切换分组时惰性计算。
- **依赖**：R1。

### R13 · 内置指标收进配方库，与用户函数**同权管理**  ｜性质 ② 契约（架构变化）

- **原话要点**：删掉图层页后，**MA / BOLL / 成交量这类内置指标"找不到地方去了"**；
  所以打算**直接在配方库里内置一些常用指标**，让它们的地位跟配方库里的用户函数一样，便于管理。
- **设计（样板已实现）**：配方库每块里 **内置在前、你的在后**：
  - 主图块：`均线 MA 5/20/60`（内置）· `布林带 BOLL`（内置）+ 你的 3 条；
  - 副图块：`成交量`（内置）· `MACD`（内置）+ 你的 2 条；
  - 内置项带 `内置` 小标签，**只能开关、不能删改**；用户项才有 ✏ / 🗑。
- **⚠ 这是一次真实架构变化（施工时最容易踩的地方）**：
  - **真源要从"5 个 QCheckBox"改成"配方库的一份列表"**（内置 + 用户混排）。
    现在 `cb_ma / cb_boll / cb_formula / cb_vol / cb_macd` 是 **§11.5-11「单一状态源」的真源**，
    改动后它们要么降级为"投影视图"，要么退役 —— **必须二选一、不许两套并存**。
  - 顶栏 chips 的候选池 `CHIP_POOLS` 现在是**硬编码 3+5 项**（`ui/widgets/chip_mru.py`）
    ⇒ 要变成**动态取自配方库**。
  - `render_charts` 的渲染顺序 / 图层构建（`desk_layers`、`chart_layers`）要按"列表"驱动，
    不能再按固定的 `cb_*` 分支。
- **✅ 内置项不改名（四轮拍板）**（原话）："内置**不要改名**，因为内置就代表这是给不懂得用户用的，
  再给他修改权限很有可能用户都不知道怎么改回来。"
  ⇒ 内置项**只读名称**，常驻「管理模式」也不出现 ✏/🗑。
- **✅ 但参数必须能调**（原话）："但是比如 MACD 这类的会有个**参数设置**的环节，
  要保留一个**给用户改参数的窗口**。" ⇒ 内置项若**有参数**，右侧给一个 **`⚙`** 入口（见 R16）；
  `成交量` 这类**没有参数**的就不给 ⚙（**有就是有、没有就是没有**，不做假入口）。

### R14 · 顶栏「＋ 更多」= 配方库的**自动镜像**  ｜性质 ① UI（不存第二份状态）

- **原话要点**：图层页删掉后，用户在配方库里使用的**主图 / 副图会自动显示在工具栏的「更多」中**。
- **设计（样板已实现）**：点顶栏「＋ 更多」弹出一张表，内容 = **配方库同一类**的全部条目，
  按「内置 / 你的配方」两段列出，点一条即开关，右侧显示`已开 / 已关`。
  - 主图「＋ 更多」= 配方库「主图」类；附图「＋ 更多」= 配方库「副图」类。
- **纪律**：这是**投影，不是第二份状态**（同 §7-B6-D 第 6 条）——
  在配方库新增/删除/开关一条，这里立刻跟着变；**禁止在这里单独维护一份清单**。
- **顺带收益**：附图 chips 的名字从"公式副图1"变成**配方名**（如 `③ RSI 超买超卖`），
  用户一眼知道那一格是什么，而不是"第 3 格"。**这个改动应一并做**。

### R15 · 拖拽排序 + **误触判断**（大列表专用）  ｜性质 ① UI（防手残）

- **原话要点**：小面板 ⬆⬇ 够用，**大分组就不够了** ⇒ 要**拖拽**；
  但**一定要考虑误触**，所以"拖拽这种情况最好**有个判断**"。
- **设计（样板已实现 · 三道闸）** —— 核心思路 = **让"拖"与"点"在物理上分开**：
  1. **闸 1｜先进入排序模式**：平时列表是"点 = 选中/切换标的"，**根本不响应拖动**。
     必须先点「⇅ 进入拖拽排序」，此时才出现手柄、提示条与「↺ 撤销 / ✓ 完成」。
     ⇒ 浏览时手滑不会改动任何顺序。
  2. **闸 2｜只认 ⣿ 手柄**：`draggable` 只挂在行首那个 ⣿ 上，**行本体不可拖**
     ⇒ "点行" 与 "拖行" 是两个完全不同的热区，误触概率极低。
  3. **闸 3｜可撤销**：拖错点「↺ 撤销」一键回原顺序。
     ⚠ **这里刻意用"撤销"而不是"二次确认弹窗"** —— 拖拽本身已是明确意图，
     每次拖完都弹窗会很烦；而"撤销"对"拖歪了一格"最有效、且不打断心流。
- **交互细节（务必一并做，否则拖拽在大列表里会很难用）**：
  - **落位提示线**（拖到目标行上半 ⇒ 插到它前面；下半 ⇒ 插到它后面）+ 被拖行半透明；
  - ⚠ **边缘自动滚动**：拖到列表可视区上下边缘时要自动滚动 —— 否则**几十只的列表根本拖不到远处**
    （这是大列表拖拽最容易被漏掉的一条）；
  - 拖拽结束**才落盘**（不要在 `dragover` 里一路写文件，§7-B8-R7 同款纪律）。
- **Qt 侧落地提示**：Qt 里对应 `QListWidget` 的 `InternalMove` + `setDragDropMode`
  （**注意 `NoSelection` 与拖拽的取舍**：数据管理页为消高亮用了 `NoSelection`，
  而拖拽需要选中项 ⇒ 排序模式下应临时允许选中，退出再还原）。

### R16 · `⚙` 参数窗口（内置/配方共用 · **防误删三道闸**）  ｜性质 ① UI + ② 契约（防手残）

- **原话要点**：内置**不给改名权**（怕不懂的用户改了改不回来），但 **MACD 这类必须有参数窗口**；
  若用户点开窗口**误删了参数** ⇒ ① 参数有改动且**未保存/未验证**时要**二次确认**；
  ② 或**检测到参数格式不对就恢复成默认值**。
- **设计（样板已实现 · 两道都做了，不是二选一）**：
  | 闸 | 触发条件 | 行为 |
  |---|---|---|
  | **① 二次确认** | 参数**改动过**，且**既没「应用」也没「校验」**就想关闭 | 底部换成确认条：「参数已改动，但既没应用也没校验。直接关掉就等于丢掉这次修改 —— 确定放弃？」，给「放弃改动 / 继续编辑」——**绝不静默丢改动** |
  | **② 自动回默认** | 点「应用」时参数**格式/范围不对**（空、非数字、≤0、>250） | **自动恢复成默认值**并明确告知"已恢复为 5 / 20 / 60，确认无误再点一次应用"——不放行、也不静默改 |
  | **③ 一键恢复默认** | 用户随时点「↺ 恢复默认」 | 回到出厂值，并提示"点应用才生效" |
- **「校验」的口径（你提到了"验证"，所以它必须真的存在）**：`▶ 校验参数` 用**最近的数据试算一遍**
  （复用回测页已有的缺参探测 / 哑数据试运行思路，**不要另起一套**）。
  **校验通过 = 视为已验证** ⇒ 关闭窗口时不再追问（否则用户会觉得"改了合法参数还老拦我"）。
- **⚠ 每个参数应带自己的合法范围**（不要所有参数都写 1~250）：如 `超买 50~100`、`倍数 0.5~10`；
  越界时提示"超买通常填 50~100"。**范围口径要写进 tooltip**，不能只给一个冷冰冰的"不合法"。
- **共用**：这个窗口**内置项与用户配方共用同一个组件**（§10-9：同类控件必须同一张脸）——
  内置的调 `均线 5/20/60`，用户配方调自己的参数，长得一模一样。

### R4 · 新增同级栏目「组合配置」  ｜性质 ② 大功能（独立立项 · 远期）

- **原话要点**：后续会新建一个与「市场回测」「市场行情」**同级别**的栏目，叫**组合配置**；
  里面用来调整用户分组里股票的**权重**，去设计每只股票占组合的配置有多少；
  组合配置里的组合与侧拉栏的分组标签**互通**，以方便快速调取查看。
- **重要对应关系**：这就是 §6.5「远期」早已登记的**组合级多标的引擎**
  （"指数择时后全市场挑股 + 资金分配 = 全新模块，**勿并入 M1**"）。
  ⇒ **不要再新开一条债**，应把它作为那个远期项的具体化。
- **设计要点（动工前必须先聊）**：
  1. **数据契约**：组合 = `{名称, 成分[(symbol, weight)], 再平衡规则?, 基准?}`；
     权重和自动归一（≠100% 时提示并按比例换算，不静默改数）。
  2. **互通**：组合 ↔ 分组标签双向；分组是"分类"，组合是"带权重的组合" ——
     **建议分组与组合用同一份存储的两种视图**，避免"两处改一处漏"（§11.5-11 同款风险）。
  3. **回测**：`BacktestEngine` 现状是 **LONG-only 单股**（§6.5/D2），组合回测是**新引擎能力**
     （多标的资金分配 + 再平衡），**不许顺手塞进 `core/backtest.py`**。
  4. **与既有模块的关系**：「市场回测」是单股 + 全市场筛选（M2/M3）；组合是第三件事。
- **结论**：**单独立项**，需要自己的规格轮（与 §7-B5 同级别的"立项 → 分步 → 验收"）。

### R5 · 整合「公式与配方」+「主副图叠加」→ 侧栏只留「配方库」  ｜性质 ② 整合（中）

- **原话要点**：顶栏横着的周期/复权那一栏里**已经有 chips** 可以让用户选叠加主图/副图是什么；
  侧边栏还专门留一栏，**这两个功能完全重合**，所以想整合掉；
  整合后侧边栏**直接变成一个配方库的展示页面**，用户直接在配方库里编辑公式然后保存。
- **设计**：
  - **删掉 `◫ 主图叠加 / 附图` 页** ⇒ 图标轨 **5 项 → 4 项**：`★自选 / ƒ配方库 / ✎标注 / ⛁数据`。
    理由：该页 5 个开关（MA / BOLL / 自定义公式 / 成交量 / MACD）**在顶栏 chips 里已有同名开关**，
    而且 chips 遵循"已启用 ∪ 最近前 3"规则 ⇒ 已启用项永远可见，不存在"开了却看不见"。
  - **`ƒ 配方库` 页**：`新建/编辑公式…`（主操作）+ `当前生效` chips + `配方库` chips + `送出去`。
- **影响面（必须同批处理）**：
  - `RAIL_ITEMS` 少一项、`DeskPanel` 页数 5→4；
  - **`smoke_pages_overlay` 的「行情工作台迁移护栏」会被打破**（它钉了 5 页键与 16 个控件的父级链）
    ⇒ 必须同批更新护栏，并新增**反向断言**（`layer` 页与 `cb_ma/cb_boll/...` 的"左栏入口"不该再存在）。
  - `desk_layout.build_layer_page()` 删除；`cb_ma/cb_boll/cb_formula/cb_vol/cb_macd` **控件本身保留**
    （顶栏 chips 的真源就是它们，§11.5-11「单一状态源」不许破）。
- ⚠ **待你确认**：删掉图层页之后，**"哪个开关在开"就只能看顶栏 chips**。
  chips 只显示"已启用 ∪ 最近前 3"，所以理论上够用，但请你在样板里确认一下手感。

### R6 · 配方库必须能一眼分辨「主图 / 副图」  ｜性质 ① UI + ② 契约（治真实痛点）

- **原话要点**：用户保存函数时虽然选了主图/副图，但**从配方库载入时完全看不出**
  这个配方到底是主图的还是副图的 ⇒ 必须做**可视化分类**。
- **⭐ 三轮定稿（用户 2026-09-17）**：**"配方以后要规定去处：副图指标只能去副图，
  主图的只能在主图。"** ⇒
  - **去处只有两类 = 主图 / 副图**（用户用的就是"副图"这个词，不分"副图1/2/3"）；
  - **一去不串门**：主图配方只能叠在主图，副图配方只能进副图（应用时目标不可改）；
  - 因此"徽标 = 去处"从"近似归组"变成**语义上唯一正确**，之前那个"多段混合怎么归类"的歧义**直接消失**；
  - 副图内部的**格位**由 R7 的"顺序"决定，**配方不绑定"第几格"** ⇒ 与"可调顺序"天然不冲突。
- **设计（样板已实现）**：
  1. **分区**：`主图配方` / `副图配方` 两块（小标题带计数）；
  2. **徽标**：chip 前置彩色徽标 —— 主图 = 蓝 `#1976D2`，副图 = 紫 `#7E57C2`；
  3. **图例**：常驻一行说明「主图 = 叠在 K 线上 / 副图 = 主图下方成图」。
- **交互**：点 chip = **直接应用**；`管理模式` 才显示 ✏改名 / 🗑删除（危险动作不与高频操作同排，§10-10）。
- **✅ 多段落定（四轮拍板 · 采用建议 (a)）**：编辑器里**每段都能选目标**（v6.8 现状）⇒
  **保存时强制统一**：若段 1→主图、段 2→副图，**直接提示**「一条公式只能去一个地方，请拆成两条」。
  **不静默改写、不静默放行**（§9-Q 教训：宁可挡住，不可替用户做主、也不许装作没看见）。

### R7 · 附图：点一个生成一个 + **可调顺序**  ｜性质 ③ 真实缺陷 + ① UI

- **原话要点**：我想象的副图是**点一个副图就在主图下面生成一个，再点一个就往下再生成一个**；
  但现阶段的副图**有严格的顺序排列，用户没办法去调整顺序**。
- **代码核实（确认是真实能力缺口）**：
  - `ui/widgets/chart_host.py` 只有 `add_pane()`（**永远追加到底部**）、`remove_pane()`、
    `set_pane_stretch()`；**没有任何 `move_pane` / 排序 API**；`_reindex_rows()` 只按**当前列表顺序**重排行。
  - `ui/widgets/desk_layers.py::render_charts()` 里副图是**按硬编码顺序**创建的：
    `vol` → `macd` → 公式副图 1/2/3。
- **修法（引擎级，与 UI 解耦）**：
  1. `ChartHost` 新增 **`move_pane(name, new_index)`**（改 `_panes` 顺序 + `_reindex_rows()` + `_refit_axes()`
     —— 注意换序后"最下面那张显示日期轴"的归属会变，必须重算）；
  2. `render_charts` 改为**按用户顺序列表**创建（顺序读 `preferences.desk_ui`，记住上次）；
  3. **⚠ 关键一致性风险**：公式段的 target 是**按名字**存的（`副图1/2/3`）。
     若允许任意重排，"副图1"的语义会漂移 —— **定稿口径：顺序只影响"显示在第几格"，不改段里的 target 名**；
     同时 UI 上要说清（样板 `⇅ 排序` 面板里已写明这一点）。
- **UI 分两档（按条目数走，四轮拍板）**：
  - **条目少**（附图 ≤5）⇒ `⇅` 面板里的 **⬆⬇ 就够**（用户原话："对于分组内容比较少的面板完全够用"）；
  - **条目多**（大分组的成分清单，几十只）⇒ **必须上拖拽**（见 R15），
    ⬆⬇ 在这种量级下要点几十次，不可用。

### R8 · 附图纵轴数字长度不一 ⇒ 坐标轴缩进不一致  ｜性质 ③ 真实缺陷

- **原话要点**：随着副图变多，左侧坐标轴出现**对不齐**；有些坐标数字长、有些小数字就小，
  导致**两者的缩进完全不一致**。
- **代码核实（确认是真实缺陷）**：
  `ui/widgets/chart_style.py::style_axis()` **只设 `setPen` / `setTextPen`，从不设轴宽度**；
  而 pyqtgraph 的 `AxisItem` 宽度由**自身刻度文本自动计算** ⇒
  量柱窗格标签 `3,120,400`（9 字符）与 MACD 窗格 `-0.05`（5 字符）左槽宽度不同 ⇒ **各窗格左边缘必然错位**。
- **修法**：给**所有窗格**的 left axis 设**统一的固定宽度**：
  `axis.setStyle(autoExpandTextSpace=False)` + `axis.setWidth(W)`，
  其中 `W` = **全部窗格中最大标签宽度**（App 可在每次重渲染/换轴后统一算一次，
  收口到 `chart_style` 或 `adaptive_axis` 一处 —— 禁止各页面自己设，§10-9 同类纪律）。
  样板里已经按"固定左槽 + 标签右对齐"绘制（`shell.js` 的 `PAD_L`），可直接看效果对比。

### R9 · 附图数量用 chips 控制（保留现状做法）｜性质 ① UI

- **原话要点**：样式 A 里面的 chips 开关挺好，用户需要几个就点几个，
  既能控制副图多少，也能避免副图过多压缩主图可视范围。
- **处理**：**保留**顶栏 chips 作为副图数量的唯一开关（不再新增数字上限）。
- **补一条保险（建议）**：给主图设**最小高度**，副图数量再多也不许把主图压到不可读
  （现在副图是 `SUB_PLOT_HEIGHT=150` 定高，超过可用高度后主图会被挤扁）。

### R10 · 画线类型改「图标 + 编号」  ｜性质 ① UI

- **原话要点**：画线类型能不能采取**数字和图标结合**的方式；纯粹表格方格展示用户有些不知道是啥，
  有图标会好很多，**用户的再教育难度也会小一些**。
- **设计（A v2 已实现）**：每行 = **SVG 图标**（纯矢量、无图片资源）+ **名称** + **右侧编号**；
  选中态 = 蓝底 + 蓝框 + 加粗。
- **口径澄清**：编号是**对照编号**（1–32），其中 **1–9 兼作数字快捷键**（按数字直接切工具）；
  10 以后的编号只作对照，**不强占键位**（32 个工具本来也不可能都挂单键）。
- **注**：图标是**语义化的线型示意**（斜线=趋势、横线=水平、四条横线=斐波回调、扇形=斐波扇形…），
  不是装饰 —— 目标是"看一眼就知道画出来长什么样"。

### R11 · 画线类型要能扩到 30+ 且**一个个全展现、不显乱**  ｜性质 ① UI（架构预留）

- **⭐ 二轮定死（用户原话）**：**"标注工具里绝对不能添加搜索栏，因为用户根本不会去用这个功能，
  所以现阶段唯一且仅有的就是一个个展现，唯一能设计的就只有如何表现这么多画线类型，让用户看着不乱。"**
  ⇒ **禁止搜索框、禁止"更多类型"折叠收纳**。设计空间**只剩一个**：怎么把 30+ 种摆得不乱。
- **设计（A v2 已按 32 种全部直出）** —— 靠四件事让"多"不显乱，**不靠隐藏**：
  1. **按类分组**（6 类：趋势/通道 · 水平/垂直 · 形态 · 斐波/分割 · 时间/测量 · 文字/标记）；
  2. **每类一个色相**（分类色条 + 该类的图标都同色）⇒ 视线能"按颜色分块"，这是最关键的一条；
  3. **统一行式**「图标 · 名称 · 编号」，名称不截断、编号一律右对齐；
  4. **固定可视高度 + 内部滚动 + 吸顶分类标题**（滚动时当前类名一直挂在顶上，不会"滚丢"）。
- **面板高度不随类型数增长**（这是"不影响观感"的硬指标；新增类型只是列表变长，不改版式）。
- **数据侧预留**：`data/annotations.py` 的 `KIND_*` 需支持"只登记、暂不渲染"的**未实现态**
  （与 v6.5 的 `kind='unsupported'` 同思路）：类型可以先出现在列表里并标注"待实现"，
  **但绝不能点了没反应也不说话**（§9-Q 教训：不静默）。

## 七、我提议的后续改进（用户 2026-09-17 开放："你要是有想法欢迎提出"）

> 下面每条都标了**为什么值得做**与**代价**；**都不挡开工**，你有空挑。
> 排序 = 我建议的优先级。

### P1 ⭐ "今天涨跌"这个词要说实话（**我最建议先做的一条**）

- **问题**：分组标签写"今天整体涨跌 +0.82%"，但**本地数据可能还停在昨天**
  （用户没点云端同步 / 当天还没收盘 / 那只股票停牌）。
  此时显示"今天"就是**假的** —— 而本项目最高指令 §10-4 是"宁可显示 `—`，绝不虚构"。
- **做法**：chip 上带**数据日期**，两种表达：
  - 数据是当日 ⇒ `核心白马 +0.82%`（正常）；
  - 数据是旧的 ⇒ `核心白马 +0.41% · 截至 09-16`（把话说全）。
  同时 tooltip 里写"本地最新到 09-16，点「☁️ 云端同步」可更新"。
- **代价**：每组的"数据日期"要跟着算（与 R3 的 LRU 一起做，几乎零额外成本）。

### P2 口径变了要**显式通知一次**，不能默默改数

- **问题**：R3 现在按等权算；以后接了 R4 的权重，**同一个标签的数字会变**。
  用户会以为"数据出错了"。
- **做法**：首次按权重生效时，提示一次"本组涨跌已改为按你在组合配置里的占比计算"，
  并把口径写在 chip tooltip 里（`等权` / `按占比`）。
- **代价**：一条提示 + 一个字段。

### P3 配方库条目多了怎么办 —— **仍然不引入搜索**

- **问题**：分组、配方都会越攒越多。但你已经明确"搜索栏用户不会用"（标注页那条），
  我认为**同一个道理适用于配方库**，不该在里面塞搜索框。
- **做法**（不靠搜索也能找得到）：① **最近使用优先排序**（与 chips 同一套 MRU 规则，
  用户已经习惯）；② 按去处**分区**（已有）；③ 在顶栏「＋ 更多」里**直接给 ⚙ / ✏ 入口**，
  减少"切到配方库 → 找到它 → 再回来"的来回。
- **代价**：主要是 MRU 排序字段（chips 已有同类实现，可复用）。

### P4 删除类动作**统一分级** + "正在生效"守卫

- **问题**：现在有"删除配方 / 删除分组 / 清空标注"三处删除，危险度不同但体验没统一。
- **做法**：按 §10-10 三级落实到三处（低危=直接删；中危=二次确认；高危=键入确认词），
  并加一条**这个项目特有的守卫**：**删一条正在生效的配方**时，必须说清
  "它会同时从图上移除"（否则用户会以为删的只是存档、图还在）。
- **代价**：小，但很防投诉。

### P5 分组 → 下一步就是"自选基金"的**净值曲线**

- **问题**：R3 只给了"今天涨跌"一个数。既然分组已经是"一只基金"，
  用户下一步一定会想看**这只基金的走势**（我这组这个月表现如何）。
- **做法**：点分组标签 → 底部/侧栏给一条**分组净值曲线**（等权或按权重合成），
  与 R4 组合配置**共用同一套计算**（先做曲线，比先做完整组合回测便宜得多）。
- **代价**：中（需要合成日序列 + 一条曲线），但收益很大、且是 R4 的自然踏板。

### P6 副图多了，主图**自动降高**而不是被压扁

- **问题**：R9 定了"副图数量由 chips 控"，但用户点到 5 个副图时，主图仍会被压得很矮。
- **做法**：设定**主图最小高度**；副图超过 N 个后，副图高度从 150px **自动降到 110px**
  （仍是定高，只是变小），并把省下的给主图。**不许让主图低于可读线**。

### P7 `⚠`（数据缺失）也要在**图标轨**上聚合

- **问题**：现在只有点开某个分组才看到 `⚠`。多个组都缺数据时用户不会发现。
- **做法**：只要**任一分组**有缺失，rail 上的 ★ 图标加一个**小黄点**，
  悬停显示"2 个分组有成分缺数据"。

### P8 参数窗口要给**每个参数自己的合理范围**

- **问题**：R16 若统一提示"要 1~250"，`超买 70` 这类会有误导（它其实是 50~100 的语义）。
- **做法**：参数带自己的范围（`超买 50~100` / `倍数 0.5~10` / `周期 1~250`），
  越界提示写人话："超买通常填 50~100"。**范围口径进 tooltip**。

### P9（远期，等 R4）组合的"再平衡"不要先做

- **提醒**：R4 的组合配置最小可用版 = **设权重 + 看涨跌 + 看净值曲线**。
  "再平衡规则 / 调仓成本 / 与实盘对照"属于**第二阶段**，
  建议先不做 —— 否则这个模块会无限膨胀（`BacktestEngine` 是 LONG-only 单股，
  组合回测等于新引擎，**别指望一版做完**）。
